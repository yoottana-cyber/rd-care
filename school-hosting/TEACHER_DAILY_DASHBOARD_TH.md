# RD CONNECT — หน้าหลักครูและเช็กชื่อรายวันที่ใช้ง่ายขึ้น

ฟีเจอร์บนสาขา `feature/teacher-daily-work-dashboard` (PR #86) พัฒนาต่อจาก PR #85
ไม่ได้นำเข้าผู้ใช้หรือนักเรียนเพิ่ม และไม่แก้ข้อมูลฐาน SQLite ในขั้นตอนพัฒนา

## หน้าหลักครู: งานของฉัน

- แสดงห้องที่ **บัญชีที่ล็อกอินเป็นครูที่ปรึกษาคนที่ 1 หรือ 2** เท่านั้น
- แสดงจำนวนสมาชิกห้องที่ลงทะเบียนในวันที่เลือก และมีรายการเช็กชื่อรายวันแล้วกี่คน
- กด **เปิดเช็กชื่อ** หรือ **ตรวจสอบหรือแก้ไข** เพื่อลิงก์เข้าหน้าเช็กชื่อของห้องนั้นโดยตรง
- ข้อมูลส่วนนี้อ่านจากเซิร์ฟเวอร์ ไม่มีชื่อ/รหัสประจำตัวนักเรียนใน API นี้ และไม่ได้เผยแพร่ข้อมูลข้ามห้อง
- ครูผู้สอนที่ไม่ได้เป็นครูที่ปรึกษายังใช้เช็กชื่อ **รายคาบ** ของตนเองได้ ไม่ได้รับสิทธิ์ดูเช็กชื่อรายวันของห้องอื่น
- รายการเช็กชื่อครบหมายถึง **บันทึกรายการแล้วครบคน** ไม่ใช่หมายถึงทุกคนมาเรียน
- ถ้าโหลดข้อมูลห้องไม่สำเร็จ ระบบจะแจ้งว่าไม่สามารถยืนยันได้ ไม่แสดงยอด 0 ที่อาจทำให้เข้าใจผิด

## ความปลอดภัยของการกรอกเช็กชื่อ

- แก้รายชื่อ/สถานะก่อนบันทึก → ระบบจะแสดง `มีข้อมูลแก้ไขที่ยังไม่ได้บันทึก`
- เปลี่ยนหน้า วันที่ ห้องเรียน รายวิชา หรือปิดหน้าเบราว์เซอร์ขณะมีการแก้ไข → เตือนก่อนออก
- ระหว่าง POST บันทึก → ปิดการแก้ไขในฟอร์มชั่วคราวและป้องกันกดส่งซ้ำ
- บันทึกสำเร็จเมื่อเซิร์ฟเวอร์ยืนยันเท่านั้น; หากเครือข่ายล้มเหลว/ผลไม่แน่นอน ระบบคงค่าที่กรอกไว้ ไม่ถือว่าบันทึกแล้ว
- ไม่คัดลอกสถานะนักเรียนลง PWA cache, localStorage หรือไฟล์ Browser ถาวร

## ทดสอบอย่างปลอดภัยก่อน Deploy

1. นำโค้ด PR #86 (รวมฐานของ PR #85) ไปลง **แอปทดสอบแยกจากเว็บจริง** โดยให้ SQLite ทดสอบเป็นไฟล์คนละตัวกับ `rd-connect-private/rd-connect.sqlite`
2. รัน `school:test`; ชุด `teacher-daily-work.test.cjs` ใช้ SQLite ในหน่วยความจำเท่านั้น
3. ล็อกอินบัญชีครูทดลองที่เป็นที่ปรึกษา 2 ห้อง ต้องเห็นเฉพาะ 2 ห้องนั้นบนหน้าหลัก
4. ตรวจว่าครูที่ปรึกษาคนที่สองมองเห็นห้องเดียวกัน และครูผู้สอนที่ไม่เป็นที่ปรึกษาไม่เห็นห้องดังกล่าว
5. เช็กชื่อรายวันด้วยข้อมูลทดสอบ → กลับหน้าหลัก ดูยอดเพิ่มขึ้นเมื่อบันทึกแล้ว
6. ทดลองแก้หนึ่งสถานะแล้วสลับห้อง/เปลี่ยนวัน/กดเมนูอื่น ต้องมีเตือนและเลือกคงข้อมูลได้
7. ทดลองตัดเครือข่ายก่อนส่ง (กับข้อมูลทดสอบเท่านั้น) ต้องไม่แจ้งว่า `บันทึกสำเร็จ` และค่าที่กรอกยังอยู่บนหน้า
8. ทดสอบมือถือ Android/iPhone, PWA อัปเดตแคช v128 และการเช็กชื่อก่อนช่วงเวลาเรียนจริง
9. เมื่อตรวจผ่านและรวม PR ครบแล้ว สำรองฐานจริงด้วย `school:backup` และเก็บไฟล์ไว้ก่อน Deploy; **ห้ามรัน `school:install` ซ้ำ**
