# RD CONNECT — ชุดแก้ไขเช็กชื่อและ QR บนเซิร์ฟเวอร์โรงเรียน

## พบปัญหาในรอบทดสอบ (31 ตุลาคม 2569)

- **รายวัน:** ผู้ใช้พบว่ารายชื่อนักเรียนบางครั้งหาย ต้อง Refresh
- **รายคาบ:** เปิดคาบแล้วไม่พบรายชื่อนักเรียน
- **สแกน QR มาสาย:** กล้องเปิดได้ แต่สแกน QR ที่พิมพ์จากหน้าโรงเรียนแล้วไม่ตอบสนอง
- **สำรองและกู้คืน:** ต้องตรวจจากไฟล์สำรองบนสำเนา ไม่ทับฐานข้อมูลจริง

## อัปเดตหลังทดสอบจริง: สแกน QR ผ่านแล้ว แต่รายวันติดวันที่รายคาบ (31 ต.ค. 2569)

ผู้ใช้ยืนยันว่า QR มาสายสแกนได้แล้ว และหน้ารายคาบแจ้งว่าเลือกวันที่ **30 ต.ค. 2569**
แต่บัญชีนักเรียนทดสอบ 2 คนมีการลงทะเบียนที่เริ่ม **31 ต.ค. 2569** ซึ่งเป็นการกรองวันที่ถูกต้อง
ปัญหาที่แก้เพิ่มเติมคือ เมื่อกลับเข้าเมนู **เช็กชื่อรายวัน** จากเมนูรายคาบ หน้ารายวัน
นำวันที่ 30 ต.ค. ที่เลือกไว้ในรายคาบมาใช้ต่อ

- เพิ่ม `web/attendance-date.js` แยกการเลือกวันที่เมื่อกลับเข้าเมนูรายวัน
  ให้เริ่มต้นเป็น **วันนี้ตามเวลาไทย** โดยไม่เปลี่ยนวันของคาบเรียนเดิม
- กรณีเข้าด้วยลิงก์แจ้งเตือนที่ระบุวันที่ชัดเจน ยังรักษาวันที่ลิงก์ส่งมา
- ผู้ใช้ยังสามารถเลือกดูรายวันย้อนหลังด้วยตนเองได้ ไม่ถูกรีเซ็ตขณะอยู่ในเมนูเดิม
- เพิ่มการทดสอบวันที่จากคาบ → รายวัน รวมทั้งลิงก์ย้อนหลังและสถานะระหว่างเมนู
- อัปเดต Cache PWA เป็น v120 เพื่อให้มือถือได้รับไฟล์ `attendance-date.js`

**วิธีทดสอบ:** อัปเดตไฟล์แอปจากสาขานี้ (อย่าแตะฐานข้อมูล), รัน `school:verify`,
Restart Node.js แล้วเปิด PWA ใหม่ เลือกคาบวันก่อนหน้า แล้วกดเมนูเช็กชื่อรายวัน
ต้องแสดง **31 ต.ค. 2569** (หรือวันที่ปัจจุบันขณะทดสอบ) และรายชื่อนักเรียนที่ลงทะเบียนมีผลแล้ว

**กรณีทดสอบรายคาบ:** ต้องเลือกวันที่ตรงกับวันในตารางสอน **และ**
ไม่ก่อนวันเริ่มลงทะเบียนของนักเรียน การเลือกคาบวันศุกร์ 30 ต.ค. กับนักเรียน
ที่ลงทะเบียนวันเสาร์ 31 ต.ค. จะไม่มีรายชื่อโดยถูกต้อง
หากต้องการทดสอบทันทีด้วยข้อมูลสมมติ ให้เพิ่มตารางสอนทดสอบ
สำหรับวันและวันที่ที่อยู่ในช่วงสิทธิ์และมีนักเรียนลงทะเบียนอยู่แล้ว
โดยไม่แก้วันเริ่มลงทะเบียนย้อนหลังโดยไม่มีหลักฐานจริง

## สิ่งที่แก้

1. **ไม่ใช้ Cache สำหรับรายชื่อเช็กชื่อแล้ว**: ทุกครั้งที่เข้าหน้าเช็กชื่อหรือบันทึก จะดึง `GET /api/students` ล่าสุด ลดปัญหารายชื่อที่เพิ่งนำเข้า/แก้ไขแต่หน้าจอยังจำรายชื่อว่างไว้
2. **วันเริ่มลงทะเบียน:** ถ้าเลือกวันที่ก่อนวันเริ่มลงทะเบียนของห้อง ระบบจะไม่ย้อนหลังรายชื่อนักเรียน (เพื่อรักษาประวัติ) แต่จะรายงาน *จำนวนนักเรียนที่ลงทะเบียนอยู่ปัจจุบัน* และ *วันเริ่มลงทะเบียนที่เร็วที่สุด* ให้ครูที่มีสิทธิ์เห็นเท่านั้น โดยไม่เปิดเผยชื่อในวันที่ไม่ตรงสิทธิ์
3. **QR มาสาย:** ตัวสแกนยอมรับ URL เช่น `https://ratsada.ac.th/web/rd-connect-fast/?late_qr=gate` ซึ่งเป็นเส้นทางเว็บโรงเรียน ไม่จำกัดแค่หน้าแรกของโดเมน; ลิงก์ QR เดิมของ Cloudflare ยังอ่านได้ระหว่างเปลี่ยนผ่าน; ลิงก์โฮสต์อื่นหรือเส้นทางแปลกปลอมถูกปฏิเสธ
4. **Service Worker:** เพิ่มเวอร์ชัน Cache เพื่อให้ PWA อัปเดตโค้ดใหม่
5. **ทดสอบกู้คืน:** คำสั่งใหม่สร้าง Snapshot SQLite จริงผ่าน API สำรองข้อมูล แล้วคัดลอกไปทดสอบความสมบูรณ์ในโฟลเดอร์ชั่วคราว (ตรวจ schema hashes, Foreign Keys, จำนวนแถว, ห้องเรียน 48 ห้อง) ก่อนลบสำเนาทดสอบโดยอัตโนมัติ **ไม่เขียนทับฐาน SQLite หลัก**

## วิธีอัปเดตและตรวจครั้งเดียว

1. ดาวน์โหลดสาขา `fix/school-attendance-qr-backup-restore` ทั้งโฟลเดอร์จาก GitHub แล้วอัปโหลดไฟล์แอป `rd-connect-school-app` ในตำแหน่งเดิม ห้ามทับ `/home/ratsadaa/rd-connect-private/` หรือ `/home/ratsadaa/rd-connect-backups/`
2. ใน DirectAdmin ตรวจว่ามี Environment Variables เดิม `RD_SQLITE_FILE`, `RD_SQLITE_BACKUP_DIR`, `RD_APP_MOUNT` และ `RD_PUBLIC_ORIGIN` ครบ ไม่ต้องตั้งตัวแปรเริ่มต้น/สร้าง Admin ใหม่
3. กด **Run NPM Install** หากมีการเปลี่ยน dependency; รุ่นนี้ใช้ `qrcode-generator` ตามเดิม
4. Run JS Script **`school:verify`** เพียงคำสั่งเดียว

คาดหวัง:

```text
[1/3] ORIGINAL WORKER, ENROLLMENT, SCHOOL PWA AND QR TESTS: OK.
[2/3] FRESH PRIVATE SQLITE BACKUP: VERIFIED.
[3/3] BACKUP RESTORED TO ISOLATED COPY: INTEGRITY, FK, SCHEMA AND COUNTS OK.
SCHOOL VERIFICATION PASS: CURRENT DATABASE UNCHANGED / NO REAL PUSH / NO IMPORT.
```

`returncode: 0` เป็นการผ่านเฉพาะชุดตรวจนี้ ไม่ใช่การยืนยันว่า Push Notification หรือสิทธิ์ทุกประเภทพร้อมเปิดใช้งานจริง

5. Restart Node.js App ผ่าน DirectAdmin; บนมือถือปิดแล้วเปิด PWA หรือโหลดใหม่เพื่อรับ Service Worker รุ่นใหม่
6. ทดสอบด้วย **ข้อมูลจำลอง** ในห้องเดิม: เปิดเช็กชื่อรายวัน → กลับมาเช็กซ้ำโดยไม่ Refresh → เลือกคาบในวันที่มีผลการลงทะเบียน → สแกน QR จาก **หน้าโรงเรียน** → ยืนยันมาสายตามขั้นตอนหลัง 08:00 น.
7. ถ้ารายคาบยังพบ 0 คน ให้ดูข้อความ “วันที่เริ่มลงทะเบียนที่เร็วที่สุด” ในหน้ารายคาบและวันคาบที่เลือก ไม่เปลี่ยน/ย้อนหลังวันเริ่มลงทะเบียนโดยไม่ตรวจสอบความถูกต้อง

> ไม่จำเป็นต้องรัน `school:install` ซ้ำ เนื่องจาก SQLite และแอดมินติดตั้งเรียบร้อยแล้ว อย่าลบฐานหรือสร้างใหม่เพื่อแก้บั๊ก

## ขอบเขต

ตัวทดสอบกู้คืนสร้างไฟล์สำรองใหม่ แล้วคืนค่าลงไฟล์สำเนาอิสระชั่วคราวจาก Backup ล่าสุดที่เพิ่งสร้าง โดยตรวจโครงสร้างและนับข้อมูลเทียบกับ Backup ก่อนลบสำเนา ไม่มีการเขียนทับ SQLite หลักหรือ Cloudflare D1 และไม่มีข้อมูลส่วนบุคคลในผลทดสอบ
