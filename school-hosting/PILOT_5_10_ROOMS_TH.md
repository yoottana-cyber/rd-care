# RD CONNECT — แผนทดลองใช้งานจริง 5–10 ห้องเรียน

สถานะ: เตรียมตรวจความพร้อม **ไม่ใช่การเปิดใช้ทั้งโรงเรียนโดยอัตโนมัติ**

## 1. อัปเดตโค้ดและตรวจความพร้อมแบบอ่านอย่างเดียว

อัปโหลดโค้ดจากสาขา `ops/school-limited-pilot-readiness` เฉพาะโฟลเดอร์แอป `rd-connect-school-app`
โดย **ห้ามทับ** `rd-connect-private` และ `rd-connect-backups` และ **อย่ารัน `school:install` ซ้ำ**.

ใน DirectAdmin > Setup Node.js App > Run JS Script ให้รัน

    school:pilot-check

คำสั่งนี้จะ **อ่านเท่านั้น** จากฐาน SQLite และ Snapshot ล่าสุด ไม่ส่ง Push ไม่เพิ่มบัญชี ไม่เช็กชื่อ ไม่ลบหรือแก้ไขข้อมูลที่มีอยู่ และไม่พิมพ์ชื่อ/รหัสผ่าน/รายชื่อนักเรียน

ตรวจ:

- HTTPS origin / mount และความครบถ้วนของ Migration เดิม
- SQLite integrity และ foreign keys
- ห้องเรียน 48 ห้อง, จำนวนครูผู้ใช้, ห้องที่มีครูที่ปรึกษา, ห้องที่มีนักเรียน
- ยอดรวมบัญชีนักเรียน ผู้ปกครอง และการเชื่อมผู้ปกครองกับนักเรียน
- มี Backup ล่าสุดอยู่ในพื้นที่ส่วนตัว และอ่าน Schema/Integrity ผ่านหรือไม่
- มี Environment Variables ใช้สร้างแอดมินชั่วคราวตกค้างหรือไม่ (ถ้ามี **หยุด**)
- การตั้งค่า VAPID ครบ 3 รายการหรือไม่ โดยไม่แสดงค่า Secret

**สำคัญ:** `returncode: 0` แปลว่า *อ่านตรวจผ่าน* เท่านั้น ไม่ได้แปลว่าครบเงื่อนไขเปิดใช้จริง; ถ้าห้องนำเข้ายังไม่ครบจะขึ้น `PILOT PREPARATION PENDING`.
ต้องตรวจ Cron และ Push ของอุปกรณ์จริงเอง เพราะคำสั่งอ่านอย่างเดียวไม่สามารถทราบกำหนดเวลาใน DirectAdmin ได้

## 2. ขอบเขตทดลอง 5–10 ห้อง

- เลือกห้องนำร่อง 5 ห้องก่อน แล้วขยายเป็น 10 เมื่อไม่มีปัญหา
- นำเข้ารายชื่อจากไฟล์ต้นทางที่โรงเรียนตรวจสอบแล้ว เฉพาะนักเรียนในห้องนำร่อง
- กำหนดครูที่ปรึกษา 1 หรือ 2 คนต่อห้องตามจริง
- ใช้บัญชีผู้ปกครองเฉพาะความสัมพันธ์ที่โรงเรียนได้ตรวจสอบแล้ว
- ยืนยันว่า **ครูแต่ละคนเช็กชื่อรายวันได้เฉพาะห้องที่ปรึกษา**; ครูผู้สอนเช็กชื่อรายคาบเฉพาะคาบที่ตนสอน
- ทดสอบข้อมูลจริงด้วยผู้ได้รับอนุญาต ไม่บันทึกชื่อหรือรหัสผ่านในภาพหน้าจอที่เผยแพร่

## 3. สำรองข้อมูลอัตโนมัติทุกวัน

- ระบบมี `school:backup` ใช้อยู่แล้ว (SQLite online backup ที่ปลอดภัยต่อ WAL)
- ให้ผู้ดูแลตั้ง **Cron ใน DirectAdmin** วันละครั้งนอกเวลาราชการ เช่น 02:00 ตามเวลาไทย
- Cron ต้องรันจาก working directory ของ `rd-connect-school-app` และใช้ Node.js/NPM ของแอปโรงเรียนจริง พร้อม Environment Variables `RD_SQLITE_FILE` และ `RD_SQLITE_BACKUP_DIR`; Cron บนโฮสต์บางแห่ง **ไม่รับค่า Environment Variables จาก Passenger อัตโนมัติ** จึงต้องทดสอบจาก Cron จริงก่อนเชื่อถือ
- ห้ามใส่รหัสผ่านแอดมินใน Cron หรือเก็บไฟล์ Backup ใน `public_html`
- ทดสอบหนึ่งรอบว่าไฟล์ Snapshot ใหม่เข้ามาใน `rd-connect-backups`; ตั้งสิทธิ์เฉพาะเจ้าของ และเก็บสำเนาอีกชุดนอกโฮสต์ตามนโยบายโรงเรียน
- อย่าลบ Backup เก่าจนกว่าระบบสำรองอัตโนมัติและการกู้คืนสำเนาจะผ่าน
- การเรียก `school:verify` เคยตรวจการกู้คืนไฟล์สำเนาแล้ว; ให้ตรวจซ้ำเป็นระยะ

## 4. Push Notification

- ต้องมี `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` ครบใน Environment Variables ของโฮสต์
- การมีตัวแปร **ไม่ได้ยืนยันการส่งถึงโทรศัพท์** ต้องให้ครู นักเรียน และผู้ปกครองที่ยินยอมสมัครรับ Push บนมือถือ
- ตรวจการส่งจริงเฉพาะข้อมูลทดสอบที่ได้รับอนุญาต และตรวจผลลัพธ์/อุปกรณ์ปลายทาง
- เดิมมีคำสั่ง `school:cron` สำหรับเรียกงานแจ้งเตือนเดิมทุก 5 นาที แต่ **ไม่ควรเปิด Cron จนกว่าจะตรวจ VAPID, ผู้รับและข้อความแจ้งเตือน**; Cron นี้อาจส่งแจ้งเตือนจริง
- หลังทดสอบผ่าน ให้ผู้ดูแลตั้ง Cron ทุก 5 นาที โดยใช้ Node.js/Environment Variables ที่ตรงกับแอป และติดตามข้อผิดพลาด ไม่เปิด Worker ซ้อนหลายตัวแบบไม่มีการตรวจ

## 5. เกณฑ์นำร่องที่ต้องผ่านก่อนขยายครบ 48 ห้อง

1. ครูอย่างน้อย 5 ห้องล็อกอิน เช็กชื่อรายวัน บันทึกและย้อนดูได้ถูกต้อง; หน้าไม่สูญรายชื่อ
2. ครูผู้สอนเช็กชื่อรายคาบของห้องที่สอน และเห็นรายชื่อเฉพาะวันที่ลงทะเบียนมีผล
3. QR มาสายยืนยันและแสดงสถานะถูกต้อง; การแจ้งเตือนถึงผู้รับที่ยินยอมจริง
4. ผู้ปกครองเห็นเฉพาะบุตรหลานที่เชื่อมไว้; นักเรียนเห็นเฉพาะข้อมูลตนเอง
5. รายการคะแนนพฤติกรรม/ความดีไม่ผิดกฎ; ไม่มีการหักคะแนนซ้ำจากการกดบันทึกซ้ำ
6. Backup อัตโนมัติอย่างน้อยหนึ่งรอบสำเร็จและตรวจไฟล์ได้ และมีสำเนาสำรองนอกโฮสต์ตามนโยบาย
7. ไม่มี HTTP 500/502, SQLite locked, ปัญหาบันทึกไม่ครบ หรือความผิดพลาดในการส่ง Push ที่ยังไม่แก้

บันทึกผลในตารางภายในโรงเรียน ไม่เปิดเผยรายชื่อนักเรียนหรือข้อมูลส่วนบุคคลให้บุคคลอื่น เมื่อผ่านต่อเนื่องระหว่างวันเรียนจริงจึงค่อยขยายจาก 5 เป็น 10 และ 48 ห้อง
