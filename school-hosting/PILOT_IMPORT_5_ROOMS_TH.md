# RD CONNECT — ตรวจไฟล์นำเข้าห้องเรียนนำร่อง 5 ห้อง

## จุดประสงค์

หลังระบบเช็กชื่อพร้อมกัน 50 ครูบน SQLite ผ่าน, VAPID และ Push ทดสอบครบทั้งครู/นักเรียน/ผู้ปกครองแล้ว
และกำลังรอผู้ดูแลโฮสต์เปิด Cron Jobs ให้ เตรียมนำเข้าข้อมูลนักเรียน **เพียง 5 ห้องนำร่องที่โรงเรียนกำหนด**
โดยไม่ต้องรอ Cron และไม่ย้าย MariaDB/Cloudflare D1

**สถานะปัจจุบันก่อนนำเข้าจริง:** โรงเรียนมี 48 ห้องในฐาน, ครูใช้งาน 1 บัญชี, ห้องที่มีนักเรียน 1 ห้อง,
นักเรียนทดสอบ 2 คน และผู้ปกครองทดสอบ 2 บัญชี ควรตรวจแยกบัญชี/นักเรียนทดสอบเดิมก่อนลงทะเบียนจริง
ไม่ลบหรือเปลี่ยนประวัติย้อนหลังโดยไม่ได้รับอนุญาต

## อัปเดตแอป

สาขา `feature/school-pilot-import-five-room-check` (ต่อจาก PR #79)

ให้อัปโหลด **โค้ดเท่านั้น** เข้า `rd-connect-school-app` เดิม
ไม่ทับ `rd-connect-private`, `rd-connect-backups`, ไม่รัน `school:install` ซ้ำ
กด Restart Node.js App และรีเฟรช PWA เพื่อรับ Service Worker v122

จากนั้นเข้า RD CONNECT ด้วย Admin → **จัดการข้อมูลนักเรียน**
จะพบแผง **“ตรวจไฟล์นำร่อง 5 ห้องเรียน — ก่อนนำเข้าข้อมูลจริง”**
ก่อนแผงนำเข้าทะเบียนนักเรียนเดิม

## เตรียมไฟล์สามชุด

ดาวน์โหลดไฟล์ตัวอย่างของระบบเดิมจากแต่ละเมนู (Excel .xlsx หรือ CSV UTF-8):

1. **ครูที่ปรึกษา**: `classroom,full_name,username,password`
2. **ทะเบียนนักเรียน**: `classroom,roll_no,student_no,full_name,username,password`
3. **บัญชีนักเรียนและผู้ปกครอง**:
   `student_no,full_name,student_username,student_password,guardian_name,guardian_username,guardian_password`

- เลขประจำตัวนักเรียน `student_no` ต้องไม่ซ้ำและเหมือนกันระหว่างไฟล์ทะเบียนกับไฟล์บัญชี ให้ตั้งชนิดคอลัมน์ Excel เป็น **Text** เพื่อรักษาเลข 0 นำหน้า
- ชื่อห้องต้องตรงตามที่แสดง เช่น `ม.1/1`; เลือก **5 ห้องจริง** จาก 48 ห้องก่อนตรวจไฟล์ อย่าคัดลอกข้อมูลตัวอย่างเข้าระบบโดยไม่แก้ไข
- ครูที่ปรึกษามี 1–2 คนต่อห้องตามจริง, ถ้าบัญชีครูมีอยู่แล้วให้เว้น Password ตามข้อกำหนดของเมนูเดิม
- สำหรับบัญชีผู้ปกครอง ให้ยืนยันตัวตนและความสัมพันธ์กับนักเรียนก่อนสร้างสิทธิ์ ในไฟล์ผู้ปกครองคนเดียวอาจมีลูกมากกว่าหนึ่งคนและใช้ Username เดิม
- บัญชีใหม่ต้องกำหนดรหัสผ่านที่ไม่ซ้ำและปลอดภัย บัญชีเดิมเว้นว่างได้เพื่อรักษารหัสเดิม แต่ตัวตรวจ **ไม่สามารถทราบจากไฟล์ว่าเป็นบัญชีใหม่หรือเดิม** จึงเตือนให้ตรวจจากฐานข้อมูลอีกครั้ง
- ไม่ใช้เลขบัตรประชาชนเป็นรหัสผ่าน และไม่ส่งไฟล์บัญชีที่มีรหัสผ่านผ่านแชตหรือพื้นที่สาธารณะ

## ขั้นตอนตรวจในเบราว์เซอร์

1. เลือก **ห้องนำร่อง 5 ห้อง** ให้ตรงกับไฟล์ที่โรงเรียนเตรียม
2. อัปโหลดไฟล์ 3 ชุดเข้าแผงตรวจ แล้วกด **“ตรวจสอบ 3 ไฟล์ โดยไม่บันทึกข้อมูล”**
3. ระบบอ่านไฟล์ในเครื่องเบราว์เซอร์ ตรวจรูปแบบภาษาไทย สถานะข้อมูลซ้ำ รายชื่อห้องนอกขอบเขต
   จำนวนครูที่ปรึกษา 1–2 คนต่อห้อง และ `student_no` ระหว่างไฟล์ทะเบียนกับบัญชี
4. ดูตารางสรุปเฉพาะจำนวนคน/ห้อง และรายการผิดพลาดโดยไม่แสดง Password
5. แก้ไฟล์ต้นฉบับแล้วตรวจใหม่จนไม่มีข้อผิดพลาด

**ความหมายของ “ตรวจผ่าน”:** ผ่านเฉพาะการเทียบไฟล์ทั้งสามชุด *ภายในเบราว์เซอร์*
ยังไม่ได้สอบทานกับบัญชีเดิม ความสัมพันธ์ผู้ปกครองหรือเลขที่จริงใน SQLite
และตัวตรวจไม่อัปโหลดไฟล์ขึ้นเซิร์ฟเวอร์ ไม่สร้างผู้ใช้งาน และไม่แก้ข้อมูลเช็กชื่อใด ๆ

## ลำดับบันทึกจริงเมื่อโรงเรียนตรวจผ่านแล้ว

**ก่อนเริ่ม:** สั่ง `school:backup` บน DirectAdmin และเก็บผลว่าผ่านก่อน

1. Admin → ครูและระบบ → นำเข้าครูที่ปรึกษา ให้กด **ตรวจสอบทั้งไฟล์ก่อนนำเข้า**
   และตรวจว่าไม่ไปทับครูที่ปรึกษาเดิม
2. Admin → จัดการข้อมูลนักเรียน → นำเข้าทะเบียนนักเรียน
   แนะนำเลือก **โหมดทะเบียนอย่างเดียว** แล้ว Preview จาก API ของฐานข้อมูลก่อนกดยืนยัน
3. Admin → บัญชีนักเรียนและผู้ปกครอง → นำเข้าบัญชี
   ตรวจว่า `student_no` มีจริงในทะเบียนหลังขั้น 2 และตรวจยืนยันความสัมพันธ์ผู้ปกครองตามเอกสาร
4. ตรวจรายชื่อ, บัญชีครู/นักเรียน/ผู้ปกครองและสิทธิ์การเข้าถึงเป็นรายห้อง,
   แล้วรัน `school:pilot-check` เพื่อดูยอดรวม; ควรมีห้องที่มีนักเรียนและครูที่ปรึกษาอย่างน้อย 5 ห้อง
5. เรียก `school:backup` อีกครั้งหลังบันทึกสำเร็จ และทดสอบกู้คืนบนสำเนาเป็นระยะ

**สำคัญ:** การนำเข้าจริงแต่ละเมนูบันทึกเป็นชุด ไม่ได้ rollback ทั้งไฟล์
หากบันทึกขาดช่วงให้ตรวจแถวที่สำเร็จก่อนนำเข้าซ้ำ ไม่ลบฐาน ไม่สั่ง `school:install`

การทดสอบ Push แบบ generic ครบทั้งสามบทบาทแล้ว แต่ Cron งานส่งซ้ำและสำรองอัตโนมัติยังรอสิทธิ์จากผู้ดูแลโฮสต์
จึงควรใช้งานนำร่องจำกัดและสำรองด้วยมือทุกวันในช่วงรอ
