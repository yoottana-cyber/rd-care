# RD Care — แยกเช็กชื่อรายวัน/รายคาบ และตารางสอนส่วนตัว

## ครูที่ปรึกษา
- **เช็กชื่อรายวัน** สำหรับห้องที่ได้รับมอบหมายเป็นครูที่ปรึกษา
- **ศูนย์ครูที่ปรึกษา** ตรวจรายการที่นักเรียนไม่เข้าคาบจากครูผู้สอน พร้อมบันทึกผล
- คิวแจ้งเตือนเป็นระบบภายใน ยังไม่ส่ง Web Push ถึงผู้ปกครองจริง

## ครูผู้สอน
1. เปิด **ตารางสอนของฉัน** แล้วเพิ่มรายการ
2. เลือกห้องเรียน วัน รหัสวิชา ชื่อวิชา และช่วงคาบ
3. ช่วงคาบรองรับ `1`, `1-2`, `2`, `2-3`, ..., `9-10`, `10`
4. กดบันทึก — **เปิดใช้งานทันทีโดยไม่ต้องผ่านผู้ดูแลอนุมัติ**
5. เปิด **เช็กชื่อรายคาบ** แล้วเลือกวันที่และคาบตามตารางของตนเอง

ครูสามารถจัดตารางสอนของตนเองได้แม้ไม่ได้เป็นครูที่ปรึกษาของห้องนั้น ระบบตรวจคาบซ้อนทั้งครูและห้องเรียน และบันทึกผู้สร้าง/ผู้แก้ไขใน audit logs

## ข้อควรทราบ
- บัญชีครูแต่ละคนแก้ไขหรือลบได้เฉพาะตารางสอนของตนเอง
- หากเคยบันทึกการเช็กชื่อรายคาบแล้ว ระบบไม่ยอมให้แก้ไขหรือลบรายการนั้น เพื่อรักษาประวัติ
- ระบบเพิ่มตารางแล้วเปิดสิทธิ์อ่านรายชื่อนักเรียนของห้องที่เลือกทันที ดังนั้น **ก่อนใช้ข้อมูลนักเรียนจริง** ควรกำหนดนโยบายยืนยันการเป็นครูผู้สอนจากทะเบียนงานวิชาการ หรือมีระบบตรวจความผิดปกติของการเพิ่มตารางสอน เพื่อป้องกันครูเลือกห้องที่ไม่ได้รับมอบหมาย
- Migration `0009_teacher_timetable_immediate.sql` ย้ายคำขอที่ค้างอยู่ให้ใช้งานได้เมื่อไม่พบคาบซ้อน คำขอเดิมที่ขัดแย้งกันจะยังปิดใช้งาน โดยครูแก้ไขข้อมูลและบันทึกใหม่ได้
- ช่อง `approval_status` ยังคงในฐานข้อมูลเพื่อรองรับข้อมูลเดิม แต่ไม่มีขั้นตอนอนุมัติอีกแล้ว

## API
- `GET /api/classrooms/catalog`: ห้องเรียนสำหรับเลือกตารางสอน
- `GET /api/my-timetable`: ตารางสอนของครู
- `POST /api/my-timetable`: เพิ่มวิชาพร้อมเปิดใช้งานทันที
- `POST /api/my-timetable/:id/update`: แก้ไขคาบที่ยังไม่เคยเช็กชื่อ
- `POST /api/my-timetable/:id/archive`: ยกเลิกคาบที่ยังไม่มีประวัติ
- `GET /api/timetable?date=YYYY-MM-DD&scope=mine`: ตารางที่ครูมีสิทธิ์เช็กชื่อในวันที่เลือก
- API เดิม `/api/admin/timetable/requests` และ `/api/admin/timetable/requests/:id/review` ยกเลิกใช้งาน
- การเช็กชื่อ **รายวัน** ยังคงจำกัดครูที่ปรึกษา ส่วน **รายคาบ** จำกัดครูผู้สอนที่เป็นเจ้าของตารางสอน

## UI แบบ Smart School (อ้างอิงแนวคิด e-Teacher)
หน้า **เช็กชื่อรายคาบ** ของครูผู้สอนมี 3 ส่วน:
1. **ตารางสอนรายสัปดาห์** แสดงวันจันทร์–ศุกร์ คาบ 1–10 (แสดงเสาร์/อาทิตย์ด้วยเมื่อมีสอน) พร้อมสีสถานะ; คาบคู่กินช่อง 2 คาบ และคลิกได้เมื่อวันที่อยู่ในช่วงที่บันทึกได้
2. **รายงานการเช็กชื่อ** เลือกช่วงวันที่ได้สูงสุด 185 วัน แยกห้อง/วิชา/คาบ สรุปมา–ไม่เข้าคาบ–สาย–ลา และเปิดดูรายชื่อพร้อมวันที่เฉพาะรายการที่ต้องติดตาม
3. **ตั้งค่าตารางสอน** เพิ่ม/แก้ไขวิชา ห้อง วัน และคาบ พร้อมเปิดใช้ได้ทันทีและกลับสู่ตารางรายสัปดาห์

เมื่อคลิกวิชาจากตารางรายสัปดาห์ ระบบเปิดหน้าเช็กชื่อพร้อมวันที่ ห้อง และวิชาที่เลือกโดยอัตโนมัติ ภาพรวมและรายงานใช้ **ข้อมูลที่บันทึกจริง** ไม่ตีความว่าการไม่บันทึกเช็กชื่อหมายถึงนักเรียนขาดเรียน

- `GET /api/my-timetable/week-status?start=YYYY-MM-DD` รับวันจันทร์เป็นจุดเริ่มสัปดาห์ แสดงจำนวนรายการที่บันทึกและรายการที่ไม่เข้าคาบ
- `GET /api/my-timetable/report?from=YYYY-MM-DD&to=YYYY-MM-DD` รายงานเฉพาะรายวิชาของผู้ใช้ที่เข้าสู่ระบบ
- เพิ่ม `&timetable_id=ID` เพื่อดูรายการไม่เข้าคาบ/สาย/ลาเฉพาะวิชาของตน (จำกัด 500 รายการต่อคำขอ)
- ทุก API กรองตามครูผู้สอน และไม่อนุญาตให้เข้าดูรายงานรายวิชาของครูคนอื่น

## บันทึกการสอนรายคาบ (ไม่บังคับ)
- เมื่อครูเปิดวิชาจากตารางสอนรายสัปดาห์ จะพบช่อง **บันทึกการสอน (ไม่บังคับ)** ใต้รายชื่อ/สถานะนักเรียน
- ใช้บันทึกหัวข้อที่สอน กิจกรรมการเรียนรู้ หรือข้อเสนอแนะได้ สูงสุด **2,000 ตัวอักษร** หรือปล่อยว่างได้
- กดปุ่ม **ยืนยันและบันทึกทั้งห้อง** เพื่อบันทึกสถานะการมาเรียนและบันทึกการสอนในรายการเดียวกัน (D1 transaction batch)
- เมื่อเปิดวิชา/วันเดิม จะดึงข้อความเดิมมาให้แก้ไขได้; ลบข้อความทั้งหมดแล้วบันทึกอีกครั้งจะลบบันทึกการสอน แต่ไม่ลบประวัติเช็กชื่อ
- หน้า **รายงานการเช็กชื่อ → รายชื่อ / บันทึกการสอน** แสดงบันทึกย้อนหลังเฉพาะวิชาของครูที่เข้าสู่ระบบ
- ฐานข้อมูลแยกตาราง `period_teaching_logs` ด้วยคีย์ `(timetable_id,school_date)`; Migration `0010_period_teaching_logs.sql`
- API เดิม `GET /api/attendance?kind=period` คืน `teaching_note` และ `teaching_note_updated_at`; `POST /api/attendance` รับ `teaching_note` เพิ่มแบบ optional โดยไม่กระทบไคลเอนต์เดิม
- รายการบันทึกการสอนแสดงในรายงานเฉพาะครูผู้สอนที่เป็นเจ้าของวิชา และไม่ถูกนำไปนับเป็นการขาดเรียนหรือสถิติการมาเรียน

## สิ่งที่ต้องทดสอบก่อนใช้จริง
- การสร้างคาบสอนพร้อมกัน คาบซ้อน และการเข้าถึงข้อมูลนักเรียน
- หน้าจอมือถือและเครือข่ายไม่เสถียร
- ความปลอดภัยข้อมูลตามนโยบาย PDPA และสิทธิ์ในการเข้าถึงข้อมูลนักเรียน
- การสำรองข้อมูล D1 และกู้คืน
