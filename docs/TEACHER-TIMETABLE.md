# RD Care — แยกเช็กชื่อรายวัน/รายคาบ และตารางสอนส่วนตัว

## การใช้งานของครูที่ปรึกษา
1. เมนู **เช็กชื่อรายวัน** แสดงเฉพาะห้องที่ครูได้รับแต่งตั้งเป็นครูที่ปรึกษา (ผู้ดูแลระบบและงานกิจการนักเรียนยังจัดการได้ตามบทบาท)
2. เมนู **ศูนย์ครูที่ปรึกษา** รวมรายการไม่เข้าคาบที่ครูผู้สอนบันทึกและรอการตรวจสอบก่อนสรุปผล
3. **การยืนยันการขาด** บันทึกคิวแจ้งเตือนภายใน ยัง **ไม่ได้ส่ง Web Push** ถึงผู้ปกครอง

## การใช้งานของครูผู้สอน
1. เปิด **ตารางสอนของฉัน** → เพิ่มรายการตารางสอน
2. เลือกห้องเรียน (ไม่จำเป็นต้องเป็นห้องที่ปรึกษาของตนเอง)
3. เลือกวันจันทร์ถึงอาทิตย์, กรอกรหัสวิชาและชื่อวิชา
4. เลือกช่วงคาบเดี่ยวหรือคู่ติดกัน: `1`, `1-2`, `2`, `2-3`, ... `9-10`, `10`
5. ส่งรายการให้ผู้ดูแลอนุมัติ เมื่อผ่านการอนุมัติจึงเลือกวิชานั้นจาก **เช็กชื่อรายคาบ** ได้
6. เลือกวันที่สอน จากนั้นเลือกวิชา-คาบและเช็กชื่อทั้งห้อง

**สำคัญ:** ครูสร้างรายการตารางสอนได้ด้วยตนเอง แต่การสร้าง **ยังไม่ให้สิทธิ์ดูข้อมูลนักเรียน** จนกว่าผู้ดูแลระบบจะอนุมัติเป็นรายวิชา-ห้อง-ช่วงคาบ การคัดกรองก่อนอนุมัติต้องยึดตารางสอนจริงของโรงเรียน

## การจัดการของผู้ดูแลระบบ
- เมนู **ครูและระบบ** → หัวข้อ **อนุมัติตารางสอนครู**: ตรวจครู วัน คาบ ห้อง รหัสวิชา และชื่อวิชา
- อนุมัติหรือไม่อนุมัติคำขอที่ครูสร้าง
- ตรวจสอบคาบซ้อนของห้องและครูก่อนเปิดรายการใช้งานจริง
- ตารางสอนที่ผู้ดูแลสร้างให้ครูโดยตรงจะอนุมัติทันที (มีสิทธิ์ `admin`)
- ตารางสอนที่อนุมัติแล้วหากครูแก้ข้อมูลจะกลับมารออนุมัติใหม่
- ไม่อนุญาตให้แก้ไขหรือลบรายการที่เคยมีประวัติเช็กชื่อ เพื่อไม่บิดเบือนข้อมูลย้อนหลัง

## API และฐานข้อมูล
- `GET /api/classrooms/catalog`: รายการห้องสำหรับครูที่ Login (ยังไม่เปิดอ่านรายชื่อนักเรียน)
- `GET /api/my-timetable`: ตารางสอนของครูและสถานะอนุมัติ
- `POST /api/my-timetable`: สร้างคำขอตารางสอน
- `POST /api/my-timetable/:id/update`: แก้ไข/ส่งตรวจใหม่
- `POST /api/my-timetable/:id/archive`: ยุติรายการที่ไม่มีประวัติเช็กชื่อ
- `GET /api/admin/timetable/requests`: คำขอที่รอผู้ดูแลพิจารณา
- `POST /api/admin/timetable/requests/:id/review`: อนุมัติหรือไม่อนุมัติ
- `GET /api/timetable?date=YYYY-MM-DD&scope=mine`: คาบที่ครูตนเองได้รับอนุมัติในวันที่เลือก
- ใช้ Migration `0007_teacher_timetable.sql` และ `0008_teacher_timetable_approvals.sql`; รองรับวิชาเก่าโดยไม่เปลี่ยนข้อมูลเช็กชื่อย้อนหลัง
- หลัง Deploy frontend ต้องตรวจ Workflow **Deploy RD Care Dev Worker** ให้ผ่านและ Migration D1 สำเร็จด้วย

## ขอบเขตที่ยังต้องพัฒนา
- ฟอร์มลาและขั้นตอนอนุมัติใบลาโดยครูที่ปรึกษา/ผู้บริหาร
- ระบบแก้ไขการเช็กชื่อย้อนหลังพร้อมเหตุผลและประวัติการเปลี่ยนแปลงละเอียด
- ผูกตารางสอนตามปีการศึกษา/ภาคเรียน, การเปลี่ยนครูผู้สอน และการจัดคาบซ้อนเฉพาะโครงการพิเศษ
- ทดสอบ UX บนโทรศัพท์จริงและทดสอบพร้อมกันหลายห้อง
- ก่อนใช้ข้อมูลนักเรียนจริง ต้องตรวจ PDPA, สิทธิ์ทุก endpoint, Backup/Restore และระบบกู้บัญชี
