# RD Care — นำเข้าครูที่ปรึกษาจาก Excel/CSV (Dev)

## ใช้ไฟล์เดียวหลายห้องเรียน
เข้าสู่ระบบด้วยสิทธิ์ **Admin → ครูและระบบ → นำเข้าครูที่ปรึกษาหลายห้องในไฟล์เดียว** แล้วดาวน์โหลดไฟล์ Excel .xlsx (ฟอนต์ Tahoma) หรือ CSV UTF-8 จากหน้าเว็บ

**หัวตาราง 4 คอลัมน์:** classroom,full_name,username,password

```csv
classroom,full_name,username,password
ม.1/1,ครูตัวอย่าง หนึ่ง,teacher_demo01,DemoTeacher#1234
ม.2/3,ครูตัวอย่าง สอง,teacher_demo02,DemoTeacher#5678
ม.3/2,ครูตัวอย่าง สาม,teacher_demo03,DemoTeacher#9012
```

- classroom = ชื่อห้องในฐาน D1 ตามที่ตั้งค่าไว้
- full_name = ชื่อ–สกุลครู ไม่เกิน 100 ตัว
- username = อังกฤษ/ตัวเลข/จุด/ขีด 3–40 ตัว
- password = รหัสเริ่มต้น **10–128 ตัวสำหรับบัญชีครูใหม่** (แนะนำรหัสยาวและไม่ซ้ำกัน เพราะรหัสผ่านสั้นคาดเดาได้ง่าย)

**ครูมีบัญชีแล้ว:** ใส่ Username และชื่อ–สกุลให้ตรงกับบัญชีครู role=teacher ที่ยังใช้งาน แล้วเว้น Password ว่าง ระบบจะผูกห้องให้โดยไม่เปลี่ยนรหัสเดิม

**หนึ่งห้องต่อครูที่ปรึกษาหลักหนึ่งบัญชี:** D1 มีเพียง classrooms.advisor_user_id หากห้องมีครูอยู่ก่อนจะไม่เขียนทับ ต้องเปลี่ยนผ่านเมนูเดิมโดยตรวจสอบก่อน

**ชื่อผู้ใช้ไม่ซ้ำภายในหนึ่งไฟล์:** ถ้าครูดูแลหลายห้อง ให้สร้างบัญชีหนึ่งครั้ง แล้วนำเข้าไฟล์อีกชุดเพื่อผูกอีกห้องโดยเว้น Password ว่าง

## ขั้นตอน
1. เลือก Excel .xlsx หรือ CSV (ตรวจจับ UTF-8 และ Windows-874/TIS-620) หรือวาง CSV
2. กด **ตรวจสอบทั้งไฟล์ก่อนนำเข้า** เพื่อทวนชื่อห้อง ชื่อครู Username รหัสผ่าน บัญชีเดิม และห้องที่มีครูที่ปรึกษาอยู่แล้ว
3. แก้ไขรายการผิดพลาดก่อนยืนยัน ทุกแถวต้องผ่านการตรวจ
4. กด **ยืนยันนำเข้าครูที่ปรึกษาทั้งไฟล์** ระบบทยอยบันทึกอัตโนมัติชุดละไม่เกิน 5 ครู เพื่อลดการใช้ CPU แต่ไม่ได้จำกัดจำนวนทั้งไฟล์
5. Backend เขียน users (teacher), classroom advisor และ audit ใน D1.batch โดยเก็บ salted PBKDF2 hash ของรหัสผ่าน ไม่มีข้อมูล Password ในผล preview
6. หากเครือข่ายขัดข้องระหว่างชุด ให้ตรวจรายการที่บันทึกไปแล้วก่อนนำเข้าซ้ำ (ไม่มีธุรกรรมครอบคลุมทั้งไฟล์)

**Dev เท่านั้น:** ก่อนนำเข้ารายชื่อ/บัญชีครูจริง ต้องผ่านการประเมินความปลอดภัยสิทธิ์ผู้ใช้งาน การรีเซ็ตรหัสผ่าน และการคุ้มครองข้อมูลส่วนบุคคล

สร้างด้วยโค้ด RD Care บน Cloudflare Workers + D1 ไม่ได้คัดลอก Google Apps Script จาก StudentPro

## ข้ามคนเดิม / อัปเดตคนเดิม (โหมดใหม่)

ใน Admin → ศูนย์จัดการระบบ → นำเข้าข้อมูล → นำเข้าครูที่ปรึกษาหลายห้อง
เลือกโหมดก่อนตรวจไฟล์ (Excel/CSV เดิมทั้ง 4 คอลัมน์ ไม่ต้องสร้างคอลัมน์ใหม่):

- **ข้ามรายการเดิม (ค่าเริ่มต้น):** เมื่อนำเข้า Username ที่เป็นครูที่ปรึกษาของห้องนั้นอยู่แล้ว ระบบข้ามทั้งแถวและไม่เปลี่ยนข้อมูลใด ๆ; ครูที่มีบัญชีแล้วแต่ยังไม่ได้เป็นที่ปรึกษาของห้องที่ระบุ จะผูกเข้าช่องว่างของห้องนั้น (ต้องมี Username และชื่อที่ตรงกับบัญชีเดิม) โดยไม่รีเซ็ตรหัสผ่าน
- **อัปเดตชื่อคนเดิม:** หาก Username เป็นที่ปรึกษาของห้องนั้นอยู่แล้วและชื่อในไฟล์ต่างจากบัญชี ระบบแก้เฉพาะชื่อที่แสดง หากครูเดิมอยู่คนละห้องและห้องปลายทางมีช่องว่าง จะผูกห้องใหม่และแก้ชื่อให้ตามไฟล์ ไม่เปลี่ยนรหัสผ่าน สิทธิ์ บทบาท หรือตารางสอน
- หากห้องมีที่ปรึกษาครบ **2 คน** ระบบจะไม่เปลี่ยนบุคคลในช่อง 1/2 เอง ต้องแก้ผ่านหน้า **ครูและตารางสอน → กำหนดครูที่ปรึกษา** โดยตรวจสอบสิทธิ์ก่อน
- หาก Username ไม่ใช่บัญชีครู/ฝ่ายกิจการที่เปิดใช้งาน ระบบไม่ผูกห้อง; Username ซ้ำในไฟล์เดียวกันยังถูกปฏิเสธเพื่อให้แน่ใจว่าไม่มีคำสั่งสร้างบัญชี/อัปเดตชื่อที่ขัดแย้งกัน
- ไฟล์ใหม่/ที่มีรายการซ้ำสามารถกดตรวจสอบก่อนบันทึกได้ โดยรายงานจำนวน **ผูกห้องใหม่ / อัปเดตชื่อ / ข้าม / ผิดพลาด** และ Password ไม่ถูกส่งคืนในผล Preview
- หากทุกแถวเป็นรายการเดิมที่ข้าม ระบบจะไม่เปิดปุ่มบันทึก ไม่ทำ DB writes
- บันทึกจริงเป็นชุดละ 5 แถว; หากเครือข่ายขัดข้องให้ตรวจข้อมูลจริงแล้วตรวจ Preview ใหม่ก่อนนำเข้าต่อ

**ก่อนนำเข้าฐานจริง:** รัน `school:backup`, ทดสอบโหมดทั้งสองบนสำเนาฐานด้วยข้อมูลสมมติ, หลังนำเข้าตรวจ `school:pilot-check` และ `school:advisor-check`. ห้ามรัน `school:install` ซ้ำ


## โหมดใหม่: แทนที่ข้อมูลครูที่ปรึกษาเดิมตามไฟล์

เมนู **นำเข้าครูที่ปรึกษาหลายห้องในไฟล์เดียว (Excel/CSV)**
เลือก **“อัปเดต/แทนที่ครูที่ปรึกษาเดิมตามไฟล์ (ใช้ข้อมูลใหม่ทับของเก่า)”** ก่อนกดตรวจสอบ

- ระบบถือว่ารายชื่อ 1–2 คนต่อห้องในไฟล์ คือ **รายชื่อครูที่ปรึกษาทั้งหมดของห้องนั้น** แล้วแทนที่ข้อมูลเก่าทั้งช่องหลักและคนที่สอง **ใน SQL เดียวกันต่อห้อง** แม้เดิมจะมีครู 2 คนอยู่แล้ว
- หากไฟล์มีเพียงหนึ่งคนในห้องนั้น ช่องครูที่ปรึกษาคนที่สองเดิม **จะถูกล้าง**; ถ้าต้องการคงไว้ต้องใส่ชื่อครูคนนั้นในไฟล์ด้วย
- ห้องเรียนที่ไม่ปรากฏในไฟล์ **ไม่เปลี่ยนแปลง**
- Username เดิมที่ใช้งานอยู่ (role teacher หรือ staff) จะถูกนำมาใช้ซ้ำโดย **ไม่เปลี่ยนรหัสผ่าน**; ถ้าชื่อในไฟล์ต่างจากชื่อบัญชี จะอัปเดตเฉพาะชื่อที่แสดง
- Username ใหม่ที่ไม่มีอยู่ในระบบต้องระบุ Password สำหรับสร้างบัญชี (ขั้นต่ำตามกฎบัญชีครูปัจจุบัน); ห้ามใช้เลขบัตรประชาชนเป็นรหัสผ่าน
- อนุญาตครูหนึ่ง Username ดูแลหลายห้องในไฟล์เดียว แต่ห้องหนึ่งห้าม Username ซ้ำ และมีได้ไม่เกิน 2 คน
- เรียงแถวของครูแต่ละห้องตามลำดับที่ต้องการให้เป็นครูที่ปรึกษาคนที่ 1 และ 2
- ตอน Preview ระบบตรวจ **ทุกห้องในไฟล์** พร้อมกันก่อนบันทึก; บันทึกครั้งละไม่เกิน 5 แถว **โดยไม่ตัดคู่ครูในห้องเดียวกันออกคนละคำขอ**
- ถ้าไฟล์อัปโหลดซ้ำและไม่มีอะไรเปลี่ยน ระบบข้ามรายการโดยไม่เขียนข้อมูลซ้ำ

ก่อนใช้กับฐานข้อมูลจริง: **สำรองด้วย `school:backup`**; ทดสอบข้อมูลจำลองบนฐานแยกก่อน; ตรวจครูแต่ละห้องในหน้าผู้ดูแลและรัน `school:advisor-check`/`school:pilot-check` หลังบันทึก

หมายเหตุ: การแทนที่ข้อมูลครูที่ปรึกษาเป็นการเปลี่ยนสิทธิ์การมองเห็นข้อมูลนักเรียน จึงต้องตรวจผล Preview และยืนยันว่ารายชื่อในไฟล์ถูกต้องก่อนกดบันทึกจริง
