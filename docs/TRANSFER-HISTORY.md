# RD Care — ประวัติการย้ายห้อง (ข้อมูลจำลอง)

## เหตุผลและโครงสร้าง

เดิมรายงานเช็กชื่ออ่านห้องจาก `students.classroom_id` ปัจจุบัน จึงไม่สามารถย้ายห้องโดยไม่กระทบข้อมูลย้อนหลัง

Migration `0004_historical_enrollments.sql` เพิ่ม:
- `student_enrollments` เก็บห้องและเลขที่ตามช่วงวัน เริ่ม `start_date` ถึงก่อน `end_date` (exclusive)
- `student_transfer_applications` บันทึกแผนและหลักฐานผู้ดำเนินการย้ายจริง
- Backfill ข้อมูลเดิมด้วย `1900-01-01` เป็นวันเริ่มต้นทางเทคนิค **ไม่ใช่วันที่เข้าเรียนจริง**
- รายชื่อและรายงานประจำวัน รายคาบ มาสาย และ Dashboard ใช้ห้องที่สังกัด ณ วันเกิดเหตุ

## วิธีทดสอบ

1. เปิด Cloudflare Pages → **นักเรียน** → เลือกห้องที่มีนักเรียนจำลอง → กด **แก้ไข**
2. กรอกปีการศึกษา ภาคเรียน และห้องปลายทาง จากนั้นกด **บันทึกแผนย้ายห้อง**
3. ตรวจรายละเอียดในตารางแผน แล้วกด **ย้ายวันนี้** ยืนยันอีกครั้ง
4. ระบบเลือกเลขที่ว่างของห้องปลายทาง บันทึกสมาชิกห้องเดิมจนถึงก่อนวันที่ย้าย และเริ่มสมาชิกห้องใหม่ในวันย้าย
5. ทดสอบเช็กชื่อของวันก่อนย้ายในห้องเดิมและของวันนี้ในห้องใหม่ พร้อมดูตารางประวัติการสังกัดห้อง

## ข้อจำกัด

- ย้ายจริงได้ **มีผลวันนี้เท่านั้น** ไม่รองรับกำหนดวันอนาคตหรือย้อนหลัง
- หากมีการเช็กชื่อหรือบันทึกมาสาย **ของวันนี้** ระบบจะปฏิเสธการย้าย
- ไม่อนุญาตให้ย้ายซ้ำในวันเดียวกัน หรือแอบย้ายผ่านฟอร์มแก้ไขทั่วไป
- เลขที่ในห้องใหม่เลือกจากเลขที่ว่าง 1–100 โดยอัตโนมัติ
- ยังไม่มีระบบโอนสิทธิ์ครูตามปีการศึกษา/ภาคเรียน, แก้ไขการย้ายย้อนหลัง, ปุ่มย้อนการย้าย และออกเอกสารการย้ายห้อง
- การแก้เลขที่ในช่วงสังกัดเดียวกันยังอัปเดตเลขที่ของช่วงนั้น ไม่ใช่เก็บประวัติทุกครั้งที่แก้เลขที่
- ยังไม่ผ่าน Load test หรือการทดสอบข้อมูลจริง ห้ามใช้กับนักเรียนจริงก่อน PDPA/QA
