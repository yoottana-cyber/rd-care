# RD Care — Roadmap และขอบเขตเวอร์ชันทดลอง

## รุ่นเริ่มต้น (MVP)
- [x] 48 ห้องเรียนแบบจำลอง
- [x] PWA บน Shared Hosting
- [x] Cloudflare Workers + D1, migrations
- [x] Login (admin/staff/teacher), สิทธิ์ห้องเรียน/ครูรายคาบ
- [x] เช็กชื่อประจำวัน, เช็กชื่อรายคาบ, บันทึกเป็นชุด
- [x] ครูลงเวลามาสาย, บันทึกคะแนนพฤติกรรม, Dashboard
- [x] คิวเหตุการณ์ขาดคาบที่รอครูที่ปรึกษาตรวจสอบ (ยังไม่ใช่ระบบ Push)

## ปรับความเร็วบนมือถือ (PWA)
- [x] โหลดรายชื่อนักเรียนและตารางสอนพร้อมกัน พร้อม cache ระยะสั้นในหน่วยความจำและ dedupe คำขอที่ซ้ำ
- [x] เคลียร์ cache เมื่อล็อกเอาต์/เซสชันหมดอายุและหลังนำเข้ารายชื่อนักเรียน
- [x] ป้องกันการวาดฟอร์มจากข้อมูลห้อง/คาบก่อนหน้าหากผู้ใช้เปลี่ยนตัวเลือกอย่างรวดเร็ว
- [ ] ทดสอบ latency และโหลดจริง 48 ห้อง พร้อมจำลองเครือข่ายมือถือที่ช้า

## เว็บทดลองบน Cloudflare Pages
- [x] เตรียม Pages Functions proxy, Service Binding และ Git-linked preview documentation
- [ ] ผู้ดูแลสร้าง Pages project/ตั้งค่า Service Binding และตรวจสอบ URL จริง
- [ ] ตรวจสอบการ Login และการทำงานบนมือถือจริงผ่าน Pages preview
- [ ] หลังพัฒนาครบค่อยย้าย PWA ไป Hosting โรงเรียน

## จัดการนักเรียนและบุคลากร (ข้อมูลจำลอง)
- [x] เพิ่ม/แก้ไข/พักข้อมูลนักเรียน และนำเข้า CSV UTF-8 จาก Excel
- [x] แสดงนักเรียนรายห้องพร้อมค้นหาและปรับเลขที่
- [x] เปลี่ยนห้องเฉพาะกรณีที่ยังไม่มีประวัติ เพื่อไม่แก้ห้องย้อนหลังโดยไม่ตั้งใจ
- [x] แก้ชื่อและพักบัญชีครู/บุคลากร พร้อมตัดเซสชันและบันทึก audit
- [x] อ่าน Excel .xlsx โดยตรงจากเบราว์เซอร์โดยไม่ส่งไฟล์ไปบุคคลที่สาม พร้อมตรวจซ้ำในไฟล์/ทั้งโรงเรียนและห้องเรียน
- [x] Preview ผลต่อแถวก่อนยืนยัน, นำเข้าแบบ all-or-nothing และแสดงเลขแถว Excel ต้นฉบับ
- [x] บันทึกแผนย้ายห้องตามปีการศึกษา/ภาคเรียนโดย **ยังไม่เปลี่ยนห้องปัจจุบัน** เพื่อรักษารายงานย้อนหลัง
- [x] โครงสร้างประวัติสังกัดห้องรายช่วงเวลา และปุ่มยืนยันย้ายจริงผ่านแผน (ย้ายได้ก่อนเช็กชื่อของวันเท่านั้น)
- [x] แยกข้อมูลรายวัน รายคาบ มาสาย และสถิติย้อนหลังตามห้องที่สังกัด **ณ วันเกิดเหตุ**
- [ ] ระบบย้ายห้องแบบล่วงหน้า/สั่งมีผลวันเปิดภาคเรียน และการแก้ไขข้อมูลย้อนหลังแบบมีเหตุผล
- [ ] รีเซ็ตรหัสผ่านครูอย่างปลอดภัย
- [ ] ทดสอบหน้าจอจัดการกับ Worker Dev + D1 และมือถือจริง

## ต่อไป ก่อน Pilot ภายในโรงเรียน
- [ ] ทดสอบและปรับปรุงการบันทึกพร้อมกัน 48 ห้อง รวมทั้ง duplicate requests และการแก้ไขชนกัน
- [ ] ผูกตารางสอนตามภาคเรียน/ปีการศึกษา และการเปลี่ยนครูคาบ/ห้องเรียนพิเศษ
- [ ] เพิ่มระบบอนุมัติใบลา, นักเรียนเข้ากิจกรรม, การลงชื่อมาสายด้วยตนเองที่ต้องยืนยัน
- [x] วางโครงสร้างคิวเหตุการณ์แจ้งเตือนภายใน D1 พร้อม dedupe โดยยังไม่ส่งข้อความจริง
- [ ] เพิ่มระบบบัญชีผู้ปกครอง ผูกสิทธิ์เด็กแต่ละคน และ Web Push หลังตรวจสอบเหตุการณ์
- [ ] ทำรายการแจ้งเตือนย้อนหลัง พร้อม retry, idempotency, unsubscribe และ fallback
- [ ] เพิ่มเครื่องมือแก้ไข/ยกเลิกการเช็กชื่อพร้อมประวัติและเหตุผล
- [ ] เพิ่มสิทธิ์ตามหน้าที่จริง รายงาน PDF/Excel และการตั้งค่ากฎคะแนนพฤติกรรม
- [ ] ทดสอบความปลอดภัย, load test, logging, backup/restore และ incident procedure

## ก่อนใช้งานข้อมูลจริง
- [ ] กำหนดผู้ควบคุมข้อมูล วัตถุประสงค์และระยะเวลาเก็บข้อมูล ตามแนวทาง PDPA
- [ ] นโยบายบัญชี/รหัสผ่าน (reset/MFA สำหรับ admin), least privilege, การหมดอายุ session
- [ ] ตรวจสอบสิทธิ์ทุก endpoint รวมถึงข้อมูลเด็กกับผู้ปกครอง
- [ ] ทดสอบความเสถียรมือถือจริงทั้ง iOS/Android, สัญญาณเน็ตไม่ดี, offline queue
- [ ] ออกแบบ partition/retention/archival ที่เหมาะสมกับโควตา D1 และข้อมูลรายคาบหลายล้านรายการ

## หมายเหตุ
โปรเจกต์นี้เป็น **ต้นแบบ** ไม่ได้เปิดใช้ Web Push จริง ยังไม่มีระบบบัญชีนักเรียน/ผู้ปกครอง และยังไม่ได้ทดสอบโหลด 1,800 คน
