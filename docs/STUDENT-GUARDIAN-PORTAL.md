# RD Care — บัญชีนักเรียนและผู้ปกครอง (ข้อมูลจำลองเท่านั้น)

## สถาปัตยกรรม

เพื่อป้องกันการข้ามสิทธิ์ ครู/ผู้บริหารและนักเรียน/ผู้ปกครองใช้ **คนละตารางบัญชีและเซสชัน**:
- `users`, `sessions`: Admin / Staff / Teacher (เดิม)
- `portal_accounts`, `portal_sessions`: Student / Guardian (ใหม่)
- `guardian_student_links`: ความสัมพันธ์ผู้ปกครองกับนักเรียนที่ Admin ตรวจสอบและยืนยัน
- `portal_login_attempts`: จำกัดการลองรหัสผ่านผิด/ล็อก 15 นาทีหลังผิด 5 ครั้ง

Migration `worker/migrations/0006_student_guardian_portal.sql` เพิ่มตาราง โดยไม่แก้ข้อมูลนักเรียนเดิมหรือเปลี่ยนชนิดของบัญชีครู

## ขั้นตอนออกบัญชี

1. เข้าสู่ระบบ RD Care เป็น **Admin**
2. เข้าเมนู **บัญชีผู้เรียน/ผู้ปกครอง**
3. **นักเรียน**: เลือกห้องและเลือกนักเรียนจำลอง ระบบกรอก `student_no` เป็น Username เริ่มต้น แต่ Admin สามารถแก้ Username และตั้ง Password เริ่มต้นเองได้
   - หากนำเข้าจาก Excel/CSV ให้ไปเมนู **นักเรียน** ก่อน แล้วกลับมาเมนู **บัญชีผู้เรียน/ผู้ปกครอง** เพื่อสร้างบัญชีจากรายชื่อทั้งห้อง ครั้งละไม่เกิน 10 คน
   - ข้อมูลนำเข้าต้องเป็น `roll_no,student_no,full_name` เท่านั้น ห้ามส่งเลขประจำตัวประชาชนหรือใช้เป็นรหัสผ่าน
4. **ผู้ปกครอง**: กรอกชื่อผู้ปกครองสมมติและ Username ใหม่ แล้วกดสร้างบัญชี
5. ระบบสุ่มรหัสผ่านชั่วคราว 32 อักขระ (สุ่ม 128-bit) และแสดงเพียงครั้งเดียว ไม่มีการเก็บรหัส plaintext ลงฐานข้อมูล
6. หากต้องการให้ผู้ปกครองเห็นข้อมูลเด็ก ให้ยืนยันตัวตน/ความสัมพันธ์ตามระเบียบโรงเรียนก่อน แล้วเลือกคู่บัญชีผู้ปกครอง–นักเรียน กดผูกบัญชี
7. สามารถเพิ่มเด็กหลายคนให้ผู้ปกครองหนึ่งบัญชี (ต้องตรวจความสัมพันธ์ **แต่ละคน**) และเพิกถอนสิทธิ์รายคนได้ทันที
8. Admin สามารถรีเซ็ตรหัสผ่านหรือระงับบัญชีได้ โดยการรีเซ็ต/ระงับจะเพิกถอนเซสชันเดิมทั้งหมด

**ในระบบทดลอง:** ใช้ชื่อและนักเรียนสมมติเท่านั้น และห้ามส่งรหัสผ่านหรือภาพรหัสผ่านในแชต/กลุ่มสาธารณะ

## นักเรียนและผู้ปกครองเข้าใช้งานอย่างไร

- เปิด Cloudflare Pages URL ของ RD Care เดิม
- ที่หน้า Login กด **นักเรียนเข้าสู่ระบบ** หรือ **ผู้ปกครองเข้าสู่ระบบ**
- ใส่ Username และรหัสผ่านชั่วคราวที่ Admin ออกให้
- **ครั้งแรกบังคับเปลี่ยนเป็นรหัสส่วนตัว 12–128 ตัวอักษร** ก่อนอ่านข้อมูล แล้ว Login อีกครั้งด้วยรหัสใหม่
- นักเรียน: อ่านการมาเรียนประจำวัน/รายคาบ มาสายและคะแนนพฤติกรรมของตนเอง
- ผู้ปกครอง: เลือกดูเฉพาะนักเรียนที่โรงเรียนผูกสิทธิ์ไว้ให้ รวมถึงข้อมูลย้อนหลังในช่วงไม่เกิน 90 วันต่อการค้นหา
- ยังไม่มีสิทธิ์เช็กชื่อ แก้คะแนนพฤติกรรม เขียนข้อมูลผู้อื่น หรือรับ Push จริง

## Privacy / Security Controls

- Portal ใช้ Bearer token คนละชุดกับครู มีระยะ 8 ชั่วโมงและแยก cookie/ที่เก็บโทเคน โดยเก็บไว้เฉพาะ `sessionStorage` ในแท็บผู้ใช้
- Password Hash ใช้ PBKDF2-SHA256 100,000 รอบ (เพื่อเข้ากับข้อจำกัด Worker ที่ใช้อยู่) และ Salt รายบัญชี; ก่อนใช้ข้อมูลจริงต้องทบทวนระบบ Auth/MFA/Rate Limiting ตามมาตรฐานปัจจุบันอีกครั้ง
- Login ทั้ง Student และ Guardian ต้องเปลี่ยนรหัสชั่วคราวก่อนดูข้อมูล
- `GET /api/portal/children` และ `GET /api/portal/records` จำกัดข้อมูลตาม `student_id` ของบัญชีนักเรียน หรือความสัมพันธ์ใน `guardian_student_links` ของผู้ปกครองที่โรงเรียนอนุมัติเท่านั้น
- การเพิกถอนลิงก์มีผลกับคำขออ่านข้อมูลครั้งต่อไป ไม่ต้องรอจนกว่าเซสชันจะหมดอายุ
- PWA Service Worker ไม่แคช URL `/api/*` และ API ส่ง `Cache-Control: no-store`
- Admin API ตรวจบทบาท `admin` ทุกครั้ง ไม่เปิดให้ผู้ปกครองผูกข้อมูลเอง
- การยืนยันความสัมพันธ์ในเวอร์ชันทดลองเป็น **ขั้นตอนของผู้ดูแล** ไม่ได้ตรวจเอกสารอัตโนมัติ; ก่อนใช้ข้อมูลจริงต้องมีกระบวนการพิสูจน์ผู้รับผิดชอบข้อมูลเด็ก/คำร้องสิทธิ์/เพิกถอนอย่างเหมาะสม

## API

| Endpoint | สิทธิ์ |
|---|---|
| POST `/api/portal/auth/login` | Public with credentials |
| GET `/api/portal/auth/me` | Portal session |
| POST `/api/portal/auth/change-password` | Portal session |
| POST `/api/portal/auth/logout` | Portal session |
| GET `/api/portal/children` | Student / Guardian หลังเปลี่ยนรหัส |
| GET `/api/portal/records?student_id=&from=&to=` | Student / Guardian หลังตรวจสิทธิ์เด็ก |
| GET/POST `/api/admin/portal/accounts` | Admin |
| POST `/api/admin/portal/accounts/:id/reset` | Admin |
| POST `/api/admin/portal/accounts/:id/status` | Admin |
| GET/POST `/api/admin/portal/links` | Admin |
| POST `/api/admin/portal/links/:guardian_id/:student_id/revoke` | Admin |

## ก่อนเปิดใช้งานจริง

ต้องตรวจสิทธิ์กับข้อมูลหลายห้องและหลายครอบครัว, ทดสอบโหลด, นโยบายผู้ควบคุมข้อมูลตาม PDPA, การแสดงผลเช็กชื่อย้อนหลังตามภาคเรียน, ขั้นตอนการพิสูจน์ตัวตนและการกู้บัญชี, ป้องกัน XSS, อุปกรณ์หาย, รีเซ็ตและเพิกถอนสิทธิ์, MFA/SSO ที่เหมาะสม รวมถึงนโยบาย retention
