# RD Care — หนีเรียนรายคาบและ Push Notification

## การใช้งาน
1. ครูผู้สอนเปิด **เช็กชื่อรายคาบ** เลือกวิชา/ห้องเรียน/วันที่
2. เลือก **หนีเรียน** เฉพาะนักเรียนที่ตรวจสอบเบื้องต้นแล้วว่ามีเหตุที่ควรแจ้ง
3. กดบันทึกทั้งห้องและยืนยันการแจ้งเตือน ระบบเก็บสถานะไว้แยกจาก **ขาด** ปกติ
4. หลังบันทึกสำเร็จ Worker เริ่มส่ง **Web Push** แบบข้อความทั่วไปไปยังอุปกรณ์ของครูที่ปรึกษาประจำห้องและบัญชีผู้ปกครองที่ผ่านการยืนยันและสมัครรับแล้วทันที ผ่าน `ctx.waitUntil` และมี cron ตรวจส่งซ้ำทุก 5 นาทีเมื่อยังส่งไม่สำเร็จ
5. ผู้ปกครองล็อกอินหน้า **ผู้ปกครอง** > รายการแจ้งเตือนหนีเรียน > **เปิดรับ Push** แล้วอนุญาตบนอุปกรณ์ โดยผู้ปกครองต้องผ่านการยืนยันตัวตน/ความสัมพันธ์และเปลี่ยนรหัสผ่านครั้งแรกแล้ว
6. ครูที่ปรึกษาเปิด **ศูนย์งานครูที่ปรึกษา** เพื่ออ่านรายละเอียดที่ผูกกับห้องของตนเอง

## หลักการสำคัญ
- ต่างจาก **ขาด** ปกติ: การบันทึกว่า **หนีเรียน** กระตุ้นการแจ้งเตือนแม้นักเรียนถูกบันทึก **ขาดรายวัน** มาก่อน
- หน้าจอล็อกแสดงเพียง `RD Care • โรงเรียนรัษฎา` และข้อความทั่วไป **ไม่มีชื่อ รหัสนักเรียน วิชา สถานะหนีเรียน หรือข้อมูลส่วนบุคคล**
- Push ไม่ได้ส่งให้ทุกคนโดยอัตโนมัติ: ต้องเปิดรับด้วยตนเองบนอุปกรณ์ที่รองรับและโรงเรียนต้องตั้งค่า VAPID บน Worker ให้เสร็จก่อน
- **ไม่มี SMS / LINE หรือการแจ้งเตือนผู้ปกครองที่ยังไม่เชื่อมบัญชี**; โรงเรียนอาจใช้ช่องทางตามระเบียบเดิมเมื่อผู้ปกครองยังไม่เปิด Push
- ต้องตรวจสอบเหตุการณ์ก่อนใช้สถานะนี้ การส่ง Push คือการแจ้งว่ามีเรื่องสำคัญที่ต้องตรวจสอบ ไม่ใช่การตัดสินความผิดนักเรียน
- หากครูแก้สถานะจากหนีเรียนเป็นสถานะอื่น `truancy_events.active=0` และ `period_truancy` ถูกลบ แต่ยังคง `attendance_period` ตามสถานะใหม่และประวัติการบันทึก การแจ้งเตือนที่ส่งไปแล้วไม่สามารถเรียกคืนจากโทรศัพท์ได้
- บันทึกค่า **หนีเรียน** เป็น `attendance_period.status='absent'` พร้อม `period_truancy` เพื่อไม่กระทบ CHECK ของตารางเดิม และ Query รายงานจะแสดงประเภทเป็น `truancy`
- ระบบแยก `truancy_push_deliveries` ตาม event/generation/device จึงไม่ส่งซ้ำเมื่อกดบันทึกเดิมซ้ำ การแก้สถานะแล้วบันทึกใหม่จะเป็น generation ใหม่


## การส่งแจ้งเตือนแบบลำดับความสำคัญสูง (Priority)
- **จัดลำดับสูง:** Web Push ของเหตุหนีเรียนใช้ `Urgency: high` และ `TTL: 3600` (หนึ่งชั่วโมง) แยกจาก Push งานขาดปกติที่เป็นระดับธรรมดา
- **ปลอดภัย:** ส่ง payload `{kind:'urgent_review',audience:'guardian'|'advisor'}` ที่เข้ารหัส Web Push `aes128gcm` ตาม RFC 8291 ไม่มีชื่อ เลขประจำตัว ห้องเรียน หรือสถานะของนักเรียนในข้อความ
- **มือถือเห็นความต่าง:** Service Worker แสดงหัวข้อ “มีเรื่องสำคัญต้องตรวจสอบ” โดยไม่ระบุชื่อนักเรียน ใช้ tag คนละตัวกับงานทั่วไป งานแจ้งเตือนปกติจึงไม่แทนที่การแจ้งเร่งด่วน และเมื่อแตะการแจ้งเตือนจะเปิดศูนย์ครูที่ปรึกษาหรือหน้าผู้ปกครอง
- **ภายในแอป:** เมนูแจ้งเตือนของครูแสดงการ์ดรายการสำคัญประจำวัน และผู้ปกครองมีทางลัดเข้าดูรายละเอียดเมื่อมีรายการวันนี้
- **เริ่มส่งทันที:** หลังบันทึกสำเร็จจะเรียกตัวส่งผ่าน Worker `waitUntil` โดยไม่บล็อกหน้าครู จากนั้น Cron ทุก 5 นาทีช่วยส่งซ้ำกรณีชั่วคราวที่ส่งไม่สำเร็จ
- **กันรบกวน:** แต่ละ event/generation/device ลองส่งได้ไม่เกิน 3 ครั้ง และรออย่างน้อย 2 นาทีระหว่างครั้งที่ล้มเหลว การกดบันทึกสถานะเดิมซ้ำจะไม่เริ่มรอบใหม่
- **ตรวจสอบก่อนส่ง:** ส่งเฉพาะเหตุของวันปัจจุบันตามเวลาไทย และต้องยังมีการจัดประเภทหนีเรียนที่ใช้งานอยู่ พร้อมตรวจสอบบัญชีครู บัญชีผู้ปกครอง และความสัมพันธ์กับนักเรียนขณะส่ง
- **หลังแก้สถานะ:** เหตุที่ถูกแก้ไขจะไม่สร้างการส่งใหม่ แต่การแจ้งเตือนที่ถูกส่งจากผู้ให้บริการไปแล้วไม่สามารถเรียกคืนได้
- การได้รับ Push บนโทรศัพท์จริงยังขึ้นกับระบบปฏิบัติการ สิทธิ์แจ้งเตือน อินเทอร์เน็ต และการตั้งค่า VAPID ทั้ง 3 ค่าบน Cloudflare


## เมื่อกดหนีเรียนแล้วมือถือไม่ขึ้น Push
ใน RD Care เวอร์ชันใหม่มีเครื่องมือตรวจสอบในระบบโดยไม่ต้องเปิดเผยกุญแจ:

1. **ครูที่ปรึกษา:** เข้าสู่ระบบ → **แจ้งเตือน** → **ตรวจสอบปัญหาการแจ้งเตือน** → **ส่ง Push ทดสอบถึงอุปกรณ์นี้**
2. **ผู้ปกครอง:** เข้าสู่ระบบบัญชีผู้ปกครองที่โรงเรียนเชื่อมนักเรียนแล้ว → **เปิดรับ Push** → **ส่ง Push ทดสอบ**
3. หากแจ้ง **ขาดค่า VAPID_SUBJECT** ให้เพิ่มที่ Cloudflare Workers → `rd-care-api-dev` → Settings → Variables and Secrets เป็น `mailto:` ตามด้วยอีเมลโรงเรียนจริง; ต้องมี `VAPID_PUBLIC_KEY` และ `VAPID_PRIVATE_KEY` ที่เป็นคู่เดียวกันครบด้วย
4. หากแจ้ง **device_not_registered** ให้เปิดรับ Push บนโทรศัพท์เครื่องที่ต้องการใช้ ไม่ใช่แค่เครื่องที่ครูใช้เช็กชื่อ
5. หากพบ HTTP 401/403 ให้ตรวจความถูกต้องของชุด VAPID และสมัคร Push ใหม่หลังแก้ไขค่า; HTTP 404/410 หมายถึงอุปกรณ์หมดอายุและต้องสมัครใหม่
6. หากทดสอบผ่านแต่ไม่ขึ้นบนจอ ให้ตรวจสิทธิ์แจ้งเตือนของระบบปฏิบัติการ, การติดตั้ง PWA, โหมดห้ามรบกวน, อินเทอร์เน็ต และว่าได้เปิดหน้าแอปผ่านไอคอนบน iPhone
7. Push หนีเรียนจะส่งเฉพาะเหตุของวันปัจจุบันตามเวลาไทย, นักเรียนต้องอยู่ในคาบเรียนที่ได้รับสิทธิ์, ครูที่ปรึกษาต้องผูกกับห้องเรียน และบัญชีผู้ปกครองต้องผูกและผ่านการยืนยันกับนักเรียน

**คำแปลผลการทดสอบ:** หากแสดงว่า `accepted` แปลว่าผู้ให้บริการ Push ยอมรับคำขอ ไม่รับประกันว่าโทรศัพท์แสดงขึ้นมาจริง และไม่มีการสร้างเหตุหนีเรียนเพื่อใช้ทดสอบ

การตรวจวิเคราะห์ API ให้ข้อมูลสถานะเท่านั้น **ไม่คืนค่า Secret, URL ของอุปกรณ์ Push, ข้อมูลนักเรียน หรือข้อมูลผู้ปกครอง**

## API และฐานข้อมูล
- `GET /api/truancy/advisor` แสดงเฉพาะห้องที่เป็นครูที่ปรึกษา (admin/staff ดูภาพรวม)
- `GET /api/portal/truancy` แสดงเฉพาะนักเรียนที่บัญชีผู้ปกครองได้รับการเชื่อมและยืนยันแล้ว
- `GET /api/portal/push/config`, `POST /api/portal/push/subscribe`, `POST /api/portal/push/status`, `POST /api/portal/push/unsubscribe`
- Migrations: `worker/migrations/0013_truancy_push.sql`, `worker/migrations/0014_truancy_priority_retries.sql`
- Test: `tests/truancy_migration_test.py`, `tests/truancy-push.test.mjs`

## การตั้งค่า Cloudflare
ให้ใช้ VAPID ชุดเดียวกับ Push ของครู โดยตั้งค่า Worker Secrets ตาม `docs/MOBILE-PWA-PUSH.md`:
`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`

หลัง Deploy Worker ให้ยืนยันว่า D1 Migration `0013` ผ่าน ทดสอบด้วยบัญชีครูและบัญชีผู้ปกครองที่มีการผูกนักเรียนจริง (ไม่ใช้ข้อมูลจริงใน Log หรือ Screenshots) และตรวจสอบทั้งการเปิดรับ/ยกเลิกแจ้งเตือน การแก้บันทึก และการส่งซ้ำ
