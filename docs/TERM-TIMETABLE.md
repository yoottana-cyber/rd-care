# RD CONNECT — ตารางสอนแยกภาคเรียน + ตรวจคาบซ้อน (ไม่มีการอนุมัติ)

## หลักการ

- **ครูผู้สอนสามารถเพิ่มตารางสอนเองได้โดยไม่รอ Admin อนุมัติ** เมื่อไม่ซ้อนตารางสอนคนอื่นหรือห้องอื่นของภาคเรียนเดียวกัน ระบบบันทึกแล้วเปิดให้เช็กชื่อได้ทันที
- ตรวจซ้ำที่ **ฐานข้อมูล D1** ด้วย BEFORE INSERT/UPDATE triggers จึงป้องกันกรณีครูสองคนบันทึกพร้อมกัน โดยแจ้ง HTTP 409 หากคาบชนกัน
- Admin ตรวจสอบรายวิชา ห้อง ครู และรายการที่ชนกันได้จากเมนู **ตรวจสอบตารางสอน** (อ่านอย่างเดียว) ไม่มีปุ่มอนุมัติ
- ตารางสอนทุกแถวมี `academic_year` และ `semester` เพื่อแยกรายภาคเรียน; สามารถใช้ห้อง/วัน/คาบเดิมในภาคเรียนอื่นได้
- เมื่อ Admin เปลี่ยนปีการศึกษา/ภาคเรียนที่เมนูตั้งค่าระบบโรงเรียน ครูจะเพิ่มตารางสอนในภาคเรียน **ปัจจุบัน** โดยอัตโนมัติ
- ในเมนูของครูสามารถเลือกดูตารางสอนภาคเรียนก่อนหน้าได้แบบ **อ่านอย่างเดียว**; การบันทึกและแก้ไขทำได้เฉพาะภาคเรียนปัจจุบัน (และไม่แก้ตารางที่เคยเช็กชื่อ)
- รายงานสรุปจากข้อมูล `attendance_period` เดิมยังคงอ้างอิง `timetable.id` เดิมได้ตามปกติ
- การเช็กชื่อรายคาบใหม่จะปฏิเสธตารางสอนของภาคเรียนเก่า และห้ามเช็กชื่อในวันที่อยู่นอกขอบเขตภาคเรียนปัจจุบัน หากมีการตั้งช่วงวันที่ไว้
- ชุดข้อมูลอ้างอิงรายภาคเรียนที่ทำใน PR #37 จะเลือกตารางสอนจากภาคเรียนนั้น ไม่ปะปนกับภาคเรียนอื่น

## ข้อควรระวังและการ Deploy

**มี Migration `0026_timetable_terms.sql`** ที่สร้างตาราง timetable ใหม่พร้อมรักษา Primary Keys เดิมและใช้ deferred foreign key validation ระหว่าง migration ควรสำรอง D1 และทดสอบ migration บน **rd-care-dev** ก่อนใช้งานกับข้อมูลจริง การทดสอบมี SQLite migration + foreign_key_check ผ่าน CI

- อย่าเปลี่ยนภาคเรียนกลางวันที่ครูกำลังเช็กชื่อ
- หากครูเพิ่มตารางสอนพร้อมกันในช่วงเดียวกัน รายการแรกที่บันทึกสำเร็จจะได้คาบ; อีกคนจะเห็นข้อความคาบซ้อน
- **ไม่มีการอนุมัติ** และการตรวจสอบของ Admin เป็นแบบอ่านอย่างเดียว ไม่ลบ ไม่สลับ และไม่แก้สิทธิ์
- อย่าสร้างรายการตารางสอนภาคเรียนใหม่โดยสำเนาและแก้ SQL ตารางเก่าโดยตรง; ให้ครูเพิ่มจาก UI เพื่อให้ตรวจคาบซ้อนทำงาน

รายการเช็กหลัง Deploy: `/api/health`; ครูเพิ่มคาบ; คาบซ้อนต้องแจ้งเตือน; เพิ่มคาบเดียวกันต่างภาคเรียนได้; Admin เห็นรายการในหน้า audit; เปิดรายงานประวัติเดิมได้
