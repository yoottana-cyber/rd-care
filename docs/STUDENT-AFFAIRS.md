# RD CONNECT — ฝ่ายกิจการนักเรียน

ระบบอนุญาตให้ **ผู้ดูแลระบบ (`admin`) ดูและจัดการงานฝ่ายกิจการนักเรียนได้ทั้งหมด** โดยอัตโนมัติ ส่วนครูผู้สอน (`teacher`) จะต้องได้รับมอบหมายสิทธิ์อย่างชัดเจนจากผู้ดูแลระบบก่อนจึงเข้าใช้งานได้ บัญชีบทบาท `staff` ซึ่งกำหนดเป็นฝ่ายกิจการนักเรียนอยู่เดิมยังคงเข้าใช้งานได้

## การกำหนดสิทธิ์เข้าใช้งาน

1. เข้าระบบด้วยบัญชี **ผู้ดูแลระบบ** → **ครูและระบบ** → **บัญชีบุคลากร**
2. เลือกครูที่มีบัญชีอยู่แล้ว และกด **แก้ไข**
3. ติ๊ก **มอบหมายสิทธิ์ฝ่ายกิจการนักเรียน** แล้วกดบันทึก
4. ให้ครูรีเฟรชหน้าเว็บเพื่อโหลดสิทธิ์ล่าสุด เมนู **ฝ่ายกิจการนักเรียน** จะปรากฏ
5. ยกเลิกการมอบหมายโดยเอาเครื่องหมายออกและบันทึก การเพิกถอนมีผลกับการเรียก API ครั้งถัดไป รวมถึงเซสชันที่ยังล็อกอินอยู่

ระบบแยกสิทธิ์นี้ไว้ใน `student_affairs_assignments` ซึ่งไม่เปลี่ยนบทบาทครูผู้สอน/ครูที่ปรึกษาเดิม ผู้ใช้ที่ไม่ได้รับมอบหมายจะมองไม่เห็นเมนูและเรียก API ฝ่ายกิจการนักเรียนไม่ได้ (HTTP 403) แม้เปิด URL โดยตรง ทั้งนี้ API การเลือกเกณฑ์คะแนนเพื่อบันทึกพฤติกรรมตามหน้าที่ครูยังทำงานได้ตามเดิม

## 1. ติดตามการเช็กชื่อรายวัน

- เข้าเมนู **ฝ่ายกิจการนักเรียน → ติดตามเช็กชื่อ**
- เลือกวันที่เพื่อตรวจการเช็กชื่อรายวันทุกห้อง จำนวนที่เช็กแล้ว และจำนวนที่ยังไม่ครบ
- นับจากนักเรียนที่ใช้งานในทะเบียนและมีรายการเช็กชื่อรายวันในวันนั้น **ครบทุกคน** ไม่ใช่การมีข้อมูลเพียงบางคน
- เจ้าหน้าที่สามารถกด **แจ้งเตือนครูที่ปรึกษา** สำหรับห้องที่ยังไม่ครบ ณ **วันปัจจุบัน** ได้ หนึ่งครั้งต่อห้องต่อวัน; หลังการกดจะแสดงจำนวนอุปกรณ์ที่นำส่งสำเร็จ
- ครูต้องสมัครรับ Push บนอุปกรณ์ตนเองก่อน หากไม่ได้สมัครไว้ ระบบจะแสดง `ยังไม่ได้สมัครรับ Push` และไม่อ้างว่าส่งสำเร็จ
- กดที่แจ้งเตือนแล้ว ระบบเข้าสู่หน้าล็อกอินครูตามปกติ และเปิดหน้าการเช็กชื่อห้อง/วันที่ได้รับแจ้ง โดยตรวจสิทธิ์เข้าถึงห้องตามระบบเดิมอีกครั้ง

## 2. ตั้งเวลาอัตโนมัติ

- เริ่มต้น **ปิดอยู่** จนกว่าฝ่ายกิจการนักเรียนจะบันทึกและเปิดใช้งาน
- กำหนดเวลา **ตามเวลาไทย** และเลือกวันในสัปดาห์ที่ต้องการตรวจ (เริ่มต้นจันทร์–ศุกร์ เวลา 08:30 น. แต่ยังปิดอยู่)
- สามารถเพิ่ม/ลบวันหยุดพิเศษเพื่อไม่ให้ Cron ส่ง Push วันนั้นได้
- Cloudflare Cron ตรวจทุก 5 นาที และส่งเฉพาะห้องที่ยังเช็กชื่อไม่ครบ มีครูที่ปรึกษา และตรงตามเวลา/วันทำการ
- บันทึกประวัติการส่งลงฐานข้อมูลแบบไม่ซ้ำสำหรับห้อง วัน และประเภทการแจ้งเตือน (อัตโนมัติหรือเจ้าหน้าที่กด)
- การประมวลผลอัตโนมัติจำกัด 8 ห้องต่อรอบ Cron และดำเนินการที่เหลือในการเรียกรอบถัดไป
- หากไม่มีผู้สมัครรับ Push หรือ VAPID ไม่พร้อม จะมีสถานะไม่สำเร็จ ไม่แจ้งความสำเร็จผิดพลาด
- ไม่ใส่ชื่อ รหัสนักเรียน หรือข้อมูลส่วนตัวใน payload Push

## 3. จัดการครูและหัวหน้าระดับ

- **หัวหน้าระดับ:** กำหนดครูผู้รับผิดชอบ ม.1–ม.6 จากบัญชีครูที่ใช้งานอยู่
- **ครูที่ปรึกษา:** เปลี่ยนหรือยกเลิกการมอบหมายครูที่ปรึกษาประจำห้องเรียน
- การมอบหมายใช้ `classrooms.advisor_user_id` เดิม จึงสะท้อนกับการเช็กชื่อและการแจ้งเตือนครูที่ปรึกษาในระบบ
- การเป็นหัวหน้าระดับไม่เพิ่มสิทธิ์ดูข้อมูลนักเรียนทั้งโรงเรียนโดยอัตโนมัติ; สิทธิ์ยังขึ้นอยู่กับบทบาทและ API ที่อนุญาต

## 4. คะแนนความดี คะแนนพฤติกรรม และการปรับพฤติกรรม (แยกบัญชี)

ฝ่ายกิจการนักเรียนกำหนด **เกณฑ์ทั้งสามกลุ่มแยกจากกัน** ในหน้า **ฝ่ายกิจการนักเรียน → เกณฑ์พฤติกรรม**:

1. **เกณฑ์ความผิด 4 ระดับ:** ความผิดเล็กน้อย, ความผิดปานกลาง, ความผิดร้ายแรง, ความผิดร้ายแรงมาก — บันทึกค่าลบเพื่อสะสมคะแนนความผิด
2. **เกณฑ์ความดี:** บันทึกค่าบวกเพื่อสะสมคะแนนความดี **เท่านั้น** ไม่ถูกนำมาใช้ลดความผิด
3. **เกณฑ์ปรับพฤติกรรม:** ฝ่ายกิจการนักเรียนสร้างชื่อและจำนวนคะแนนปรับ เช่น “ปรับพฤติกรรม 5 คะแนน” และ “ปรับพฤติกรรม 10 คะแนน” จากนั้นเลือกเปิด/ปิดเกณฑ์นี้ได้ ไม่ตั้งเกณฑ์เองโดยอัตโนมัติ

ในหน้าครูมีเมนู **คะแนนพฤติกรรม** กับ **คะแนนความดี** แยกจากกัน ครูเลือกเกณฑ์ที่เปิดใช้งานโดยฝ่ายกิจการนักเรียน บันทึกเหตุการณ์โดยระบบรับคะแนนจากเกณฑ์บนเซิร์ฟเวอร์ ไม่รับคะแนนที่พิมพ์ส่งเอง

**คำนวณเป็นสองยอดอิสระ:**

- คะแนนความดี = ผลรวมรายการความดี (รวมรายการบวกเดิมที่ยังไม่ระบุประเภท)
- คะแนนความผิดสะสม = ผลรวมของคะแนนติดลบในตารางประวัติ
- คะแนนที่ปรับพฤติกรรมแล้ว = ผลรวมรายการ `adjustment` ที่บันทึกจากเกณฑ์ปรับพฤติกรรม
- คะแนนความผิดคงเหลือ = `max(0, คะแนนความผิดสะสม - คะแนนที่ปรับพฤติกรรมแล้ว)`
- คะแนนความดี **ไม่รวมอยู่ในสมการ** หักล้างคะแนนความผิด

ตัวอย่าง: ทำความดี **20 คะแนน**, มีความผิด **10 คะแนน** → ความผิดคงเหลือ **10 คะแนน** ไม่ใช่ 0; หากปรับพฤติกรรมตามเกณฑ์ **5 คะแนน** → คงเหลือ **5 คะแนน**, ความดียัง **20 คะแนน**

**ความปลอดภัยและการคงประวัติ:** API เดิม `POST /api/behavior` ถูกปิดไม่ให้บันทึกคะแนนอิสระ; API ปรับพฤติกรรมต้องรับ `adjustment_rule_id` ของเกณฑ์ที่เปิดใช้ และจะตรวจยอดความผิดคงเหลือก่อนบันทึกแบบ atomic ห้ามปรับเกินยอดคงเหลือ (ไม่สะสมเครดิตปรับพฤติกรรมล่วงหน้า) ระบบเก็บชื่อ ผู้บันทึก เหตุผล วันเวลา และ audit log ทุกครั้ง; ห้ามครูทั่วไปบันทึกการปรับพฤติกรรม

ประวัติเดิมไม่ถูกลบ ไม่แก้ย้อนหลัง โดยแสดงคะแนนบวกเดิมที่ไม่มีประเภทเป็น **ความดี**, คะแนนลบเดิมเป็น **คะแนนความผิด**, และคะแนนบวกเดิมที่ระบุ `adjustment` เป็น **ปรับพฤติกรรม** โดยเฉพาะ ทั้งนักเรียนและผู้ปกครองเห็นยอดทั้งสองประเภทแยกกันในช่วงวันที่เลือก

## 5. ภาคทัณฑ์และทัณฑ์บน

ทะเบียนมาตรการแยกจากคะแนนพฤติกรรม โดยบันทึก:

- ผู้เรียนและวันที่เกิดเหตุ
- มาตรการ (ภาคทัณฑ์หรือทัณฑ์บน)
- รายละเอียดข้อเท็จจริงและเงื่อนไขข้อตกลง
- วันที่แจ้งผู้ปกครองและวันที่รับทราบ (ถ้าผู้ดำเนินการมีหลักฐาน)
- สถานะ `ดำเนินการอยู่`, `เสร็จสิ้น`, `ยกเลิก` และบันทึกติดตามผล
- ผู้บันทึก ผู้ตรวจสอบ และประวัติการแก้ไขใน audit log

**ข้อควรระวัง:** การบันทึกมาตรการเป็นทะเบียนภายในฝ่ายกิจการนักเรียน ไม่ได้ถือเป็นคำสั่งลงโทษที่มีผลอัตโนมัติ และไม่ใช่ลายมือชื่ออิเล็กทรอนิกส์ของนักเรียนหรือผู้ปกครอง ควรดำเนินการและจัดเก็บเอกสารประกอบตามระเบียบที่โรงเรียนอนุมัติ

## การเผยแพร่

1. GitHub Actions `Check RD CONNECT` ต้องผ่าน
2. GitHub Actions `Deploy RD CONNECT Dev Worker` จะใช้ migration `0018_student_affairs.sql` `0019_student_affairs_role_assignments.sql` และ `0020_separate_merit_conduct_adjustments.sql` ก่อน deploy
3. ตรวจสอบ Cloudflare Pages ว่าเผยแพร่ `web/student-affairs.js` และ `web/student-affairs.css` พร้อม Service Worker เวอร์ชันใหม่
4. ทดสอบบัญชี `admin`, `staff` และบัญชีครูที่ได้รับมอบหมายสิทธิ์ กับเมนูฝ่ายกิจการนักเรียน รวมถึงการเพิกถอนสิทธิ์
5. ทดสอบครูที่ปรึกษารับ Push ทดสอบก่อนเปิดระบบเตือนอัตโนมัติ
6. กำหนดเกณฑ์คะแนนตามระเบียบโรงเรียนที่ได้รับอนุมัติ แล้วจึงเริ่มใช้บันทึกจริง

ไม่ต้องเปลี่ยนโดเมน, VAPID, บัญชีเดิมหรือ Push subscriptions.
