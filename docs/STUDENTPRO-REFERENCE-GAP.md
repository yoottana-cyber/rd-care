# RD Care — รายการฟังก์ชันจากไฟล์ StudentPro ที่ผู้ใช้แนบ (25 ตุลาคม 2569)

**ข้อมูลอ้างอิง:** ไฟล์ HTML ที่ผู้ใช้แนบมีชื่อหน้า StudentPro / ระบบจัดการข้อมูลนักเรียน บรรจุหน้าแอปบน Google Apps Script. วิเคราะห์เฉพาะโครงสร้างเมนูและชื่อฟังก์ชันที่มองเห็นในไฟล์ ไม่ใช่ซอร์สของ Worker/D1 และไม่ได้ทดสอบฟังก์ชันออนไลน์ทุกปุ่ม.

## 1) หน้าจอและความสามารถที่พบในไฟล์ต้นทาง

- UI: แถบเมนูด้านข้างที่ย่อ–ขยายได้, แถบเมนูมือถือ, ค้นหานักเรียนจากส่วนกลาง, ธีมสี/โหมดมืด, Dashboard การ์ดสี, กราฟสถิติการเข้าเรียน, รีเฟรชข้อมูล
- วิชาการ: ตารางเรียน, ตารางสอนครู, สับคาบสอน, เช็กชื่อประจำวัน/รายวิชา, ประวัติเช็กชื่อ, วันหยุด, ชดเชยคาบเรียน
- ดูแลนักเรียน: บันทึกพฤติกรรม, กำหนดกฎคะแนน, ประวัติ, บัตรความดี/ของรางวัล, คำร้องลา/อนุมัติ, หอพัก/เช็กชื่อหอพัก, ผู้ปกครองตรวจข้อมูล
- ธุรการ/ระบบ: นำเข้า/ย้ายชั้น/ศิษย์เก่า, ตั้งค่าหัวหน้าห้อง, รายงาน PDF/Excel, บันทึก Audit, สำรอง/กู้คืน, Maintenance Mode

## 2) เปรียบเทียบกับ RD Care

| กลุ่ม | สถานะก่อนงานนี้ | สิ่งที่เพิ่มใน PR นี้ |
|---|---|---|
| Dashboard สีและธีม | มีอยู่แล้วจาก PR #19 | คงสีและธีมเดิม |
| เมนูย่อ–ขยายบนคอม | มีเมนูแถวบน | เพิ่ม Sidebar ย่อ/ขยายได้ พร้อมแสดงเมนูตาม Role |
| เมนูมือถือ | มีแถบเมนูล่างเลื่อนได้ | คงไว้; หน้าใหม่ไม่บังแถบเมนูล่าง |
| ค้นหานักเรียนทั่วโรงเรียน | ค้นหาได้เฉพาะห้องที่เลือก | เพิ่ม API ค้นหาทั่วโรงเรียน เฉพาะ Admin, จัดลำดับผลลัพธ์และเปิดหน้ารายคน |
| เช็กชื่อประจำวัน/รายคาบ | มี Worker+D1 | คงฟังก์ชันเดิม |

| ตารางเรียน/สับคาบ/วันหยุด/อนุมัติใบลา | ยังต้องมีข้อมูลและกระบวนการใหม่ | อยู่ในแผนพัฒนาถัดไป |

| กราฟรายเดือน/ปี, PDF, หอพัก, แลกรางวัล | ต้องออกแบบข้อมูล การอนุญาต และการทดสอบ | ยังอยู่ในแผนพัฒนา ไม่รวมใน PR นี้ |
| สำรองข้อมูล/กู้คืน | ต้องออกแบบ Workflow ข้อมูลจริงและสิทธิ์แยก | ยังไม่เพิ่มใน PR นี้ |

## 3) หลักการพัฒนาต่อ

1. ทำ UI ให้สอดคล้องกับตัวอย่าง โดยสร้างโค้ด RD Care เอง ไม่คัดลอกแอป StudentPro.
2. พัฒนาฟังก์ชันที่ต้องแก้ฐานข้อมูลแยก PR พร้อม D1 migrations, regression tests, role checks, audit และ backup ที่เหมาะสม.
3. ขั้นถัดไปแนะนำ (ตามประโยชน์ใช้งาน): ประวัติเช็กชื่อพร้อม Export และกราฟแนวโน้ม → ตารางเรียน/ตารางสอน → ใบลา/อนุมัติ → พฤติกรรมขั้นสูง → รายงานและสำรองข้อมูล.
4. ระบบ Dev ยังใช้ข้อมูลสมมติ ไม่ใช้ข้อมูลนักเรียนจริงจนกว่าจะตรวจ PDPA และทดสอบสิทธิ์/โหลดจริง.

**ข้อควรระวัง:** ฟังก์ชันใน StudentPro ใช้ Google Apps Script/Google Sheets/Google Drive จึงนำไปวางแทน Cloudflare Worker+D1 ตรง ๆ ไม่ได้.
