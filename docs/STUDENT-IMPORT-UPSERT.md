# นำเข้าทะเบียนนักเรียนแบบ Upsert + ข้ามแถวผิดพลาด

ในเมนู **จัดการนักเรียน → นำเข้าจาก Excel/CSV ทั้งโรงเรียน** ให้นำเข้าข้อมูลหลายห้องในไฟล์เดียว ระบบตรวจตาม **เลขประจำตัวนักเรียน**:

- เลขประจำตัว **ยังไม่มี**: เพิ่มนักเรียนใหม่ และสร้างบัญชีนักเรียนเมื่อมี Username/Password
- เลขประจำตัว **มีอยู่และอยู่ห้องเดียวกับในไฟล์**: อัปเดต **ชื่อและเลขที่** กับแถวการสังกัดห้องปัจจุบัน โดยคง `students.id` และบัญชีผู้ปกครอง
- บัญชีเดิม: Username ใหม่ที่ไม่ชนกับบุคคลอื่นสามารถอัปเดตได้; รหัสผ่าน **ว่าง = คงรหัสเดิม**, ใส่รหัสใหม่ = ตั้งรหัสใหม่อย่างปลอดภัย; ชื่อในบัญชีจะอัปเดตตามทะเบียน
- เลขประจำตัวเดิมที่ไฟล์ระบุ **คนละห้อง**: ข้ามและแจ้งใช้แผนย้ายห้องตามขั้นตอนทะเบียน ไม่เปลี่ยนห้องจากไฟล์ เพื่อรักษา `student_enrollments` และประวัติเช็กชื่อเดิม
- ชนเลขที่ในห้อง, ชน Username ของบุคคลอื่น, มีข้อมูลลบ/เก็บเป็นประวัติ, ข้อมูลไม่ถูกต้อง, หรือแถวซ้ำภายในไฟล์: **ข้ามเฉพาะแถว** พร้อมแสดงเหตุผล ไม่บล็อกทั้งไฟล์
- ฝั่ง Worker ตรวจซ้ำก่อน commit **ทุกแถว** โดย `D1.batch` แยกตามนักเรียน จึง rollback เฉพาะรายการที่บันทึกไม่สำเร็จ และประมวลผลรายการถัดไปได้
- หน้ารายงานสรุป **เพิ่ม / อัปเดต / ข้าม** และแสดงรายการสาเหตุรายแถว โดยไม่แสดง Password ในผล API หรือหน้าพรีวิว

เพื่อไม่ให้สับสน แบบฟอร์มนำเข้า CSV นักเรียนที่ซ้ำในเมนู **ครูและระบบ** ถูกแทนที่ด้วยทางลัดไปยังศูนย์ทะเบียนเดียวกัน ระบบนำเข้าครูที่ปรึกษายังอยู่ที่เดิม

**ข้อจำกัดที่ตั้งใจรักษา:** ไม่ย้ายห้อง ไม่เลื่อนชั้น ไม่คืนสถานะข้อมูลลบ และไม่แก้ประวัติการเช็กชื่อโดยอัตโนมัติจากไฟล์; ใช้เมนูทะเบียนสำหรับการเปลี่ยนสถานะเหล่านี้

การใช้งาน: นำเข้าไฟล์โดยเลือก preview ตรวจแต่ละแถวแล้วเลือกบันทึก; ระหว่างบันทึกข้อมูลจะส่งเป็นชุดย่อย แต่ Worker ดำเนินการแยกทีละแถวเพื่อให้ผิดแถวหนึ่งไม่กระทบอีกแถว

ทดสอบ regression: `node --test tests/unified-roster.test.mjs` และ workflow `tests/*.test.mjs`.


## ไฟล์จำนวนมาก เช่น 1,750 คน (แก้ HTTP 500)

เลือกไฟล์ Excel/CSV **ครั้งเดียว** ระบบแบ่งคำขอให้เบื้องหลังตามข้อจำกัด Cloudflare D1:

- ตรวจฐานข้อมูลครั้งละ **25 คน** เพื่อไม่เกิน 100 bound parameters ใน SQL และ 50 queries ต่อ Worker invocation ของแผน Free
- บันทึกครั้งละ **1 คน** ด้วย `D1.batch` ของนักเรียนคนนั้นเท่านั้น เพื่อแยกความล้มเหลวและจำกัด CPU ของการสร้างรหัสผ่าน
- แสดงผลตรวจและผลนำเข้าครั้งละ 80 แถวพร้อมปุ่มก่อนหน้า/ถัดไป และตัวกรองแถวมีปัญหา เพื่อลดภาระการวาด 1,750 แถวซ้ำ
- อัปเดตความคืบหน้าต่อเนื่อง หากคำขอมีปัญหาชั่วคราวจะเก็บสถานะ *ยังไม่ยืนยันผล* (ไม่กล่าวอ้างว่าแถวถูกข้ามหรือบันทึกสำเร็จ) ให้ดำเนินการต่อจากแถวที่ยังไม่ยืนยันได้โดยไม่ต้องเลือกไฟล์ใหม่ ตราบใดที่ยังอยู่ในหน้าเดิม
- เมื่อจบงานจะล้างข้อมูลต้นฉบับที่มี Password ออกจากหน่วยความจำของตัวนำเข้า; ไม่ส่ง Password กลับใน API responses

**ฐานข้อมูล:** migration `0030_large_roster_import_lookup.sql` เพิ่ม index ของ `lower(student_no)` และ `lower(portal_accounts.username)` เพื่อไม่ให้ค้นหาแบบเต็มตารางทุกแถว ข้อมูลนักเรียน/บัญชีและ `student_id` เดิมไม่เปลี่ยน

**ก่อนใช้งานจริง:** สำรองข้อมูล D1, ติดตั้ง migration 0030, Deploy Worker และ Cloudflare Pages เวอร์ชันล่าสุด แล้วรีเฟรชเว็บไซต์เพื่อใช้ PWA cache ใหม่ หากยังพบ HTTP 500 ให้ตรวจ Cloudflare Workers → Logs ของคำขอ `/api/admin/unified-import/preview` หรือ `/commit` เพื่อตรวจว่าสาเหตุมาจาก database quotas, CPU limit, schema mismatch หรือเหตุผลอื่น

หากเคยนำเข้าได้บางส่วนก่อน HTTP 500 สามารถใช้ไฟล์เดิมอีกครั้งได้ ระบบจะ **จับคู่เลขประจำตัวเพื่ออัปเดต** ไม่สร้างนักเรียนซ้ำ ไม่ย้ายห้องข้ามปีการศึกษา และไม่แก้ประวัติเช็กชื่อ
